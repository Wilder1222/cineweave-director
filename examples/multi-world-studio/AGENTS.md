# Codex World OS operating contract

This directory is controlled by one orchestrator: `codex.root`.

When a user asks to create a world, trigger an event, decide character behavior, continue a plot or update the platform:

1. Read `workspace.json`, the exact world source and the current terminal commit chain.
2. Run `npm run worlds:review` before proposing state changes.
3. Add executable behavior to the versioned ActionCatalog and causal EventTemplateCatalog. EventProposal may reference only catalog `actionId + parameters`; never let a proposal self-author effects or edit a generated state in place.
4. Bind the exact workspace, world, state, trigger catalog, action catalog and platform profile refs. Require the expected state version and sequence.
5. Catalog actions must cite actor goals, capabilities, knowledge, preferences, limits and world rules, with explicit costs, duration and effects. Templates must state objective, opposition, pressure choice, state change, irreversibility and next cause.
6. Prefer `world-os step/run`; in v0.4 the scheduler scans triggers, applies dueAt/cooldown/maxOccurrences, compiles Codex-authored templates into a one-to-three-candidate BranchSet, applies hard constraints before the template score and commits exactly one candidate. Treat explicit stop reasons—especially `needs_human_gate`, `awaiting_codex_template`, `all_candidates_rejected`, `stale_after_race` and `committed_projection_pending`—as terminal until their required input changes. A gated decision must go through `gate-request → gate-decide → resume`; Canon promotion is a separate exact step. `signal-ingest` is observation-only; `signal-use` records Codex's exact Proposal evidence/defer/dismiss decision without writing State or Canon. `portfolio-run` only allocates turns among independent world streams and never merges their State or Canon.
   A new world must first go through `create-world` → `world-inception-decide` → `world-activate`; a candidate registration is not runnable and must not be scheduled merely because it has a World ID. `world-activate` must bind a complete sequence-zero runtime package to the exact human approval.
   A cross-world brand motif must go through `brand-echo-create` → `brand-echo-decide` → `brand-echo-activate`. Phase 1 BrandEcho is `shared_motif_only`: it cannot change Canon, share Actor/Item refs, or create causal links between worlds.
   A production slice must bind an exact simulation Commit/State before any media work: `production-slice-create` → ordered `production-gate-decide` → `production-stage-activate`. Its snapshots are evidence pointers to provider-neutral CineWeave contracts; the release gate is private-workspace only, and no generated file, public release or external provider may be claimed without its own receipt.
   After the Rights Gate, use `production-execution-plan` to compile the exact slice into a generic `ExecutionRequest`; use `production-execution-run` so the latest slice version, adapter capability, budget, idempotency and output receipt are checked by the generic runtime. A request compiled before Rights is persisted as blocked, and a request for a stale slice cannot replay. Fixture mode is local-only; external mode requires an exact request ApprovalRecord, a trusted adapter and explicit operator enablement. An ExecutionReceipt is not QA, ApprovedAsset or Release evidence.
   For image outputs, follow a successful receipt with `production-media-import`. It re-verifies the execution-store bytes and creates only a draft PNG/JPEG/WebP `MediaImport` plus an exact `world_os_production_media_import` binding. Attach that binding ref to the human QA decision; the callback cannot approve the asset, advance the slice, or create a Release receipt. SVG/video outputs need their own future import contract and must not be relabeled as MediaImport.
   The required post-media sequence is `production-qa-review` (explicit human checklist while `qa_pending`) → QA Gate evidence → `production-stage-activate` → `production-approved-asset` → Release Gate → `production-stage-activate` → `production-private-release`. The resulting `ApprovedAsset` and `ReleaseReceipt` remain private and exact-version bound; a Gate stage alone is never treated as an asset approval or a public publish.
   For a bounded end-to-end Codex turn, prefer `world-os brain-run`: it records preflight verification, optional proposal-only LLM shadows, the weighted-fair Portfolio, MCP dry-run/explicit network dispatch and postflight verification in one `CodexBrainRunReceipt`. Do not treat the aggregate receipt as permission to skip the child Gates.
   For a continuation preview, use `world-os forecast --worlds W01,W02` or `GET /v1/brain/forecast?worlds=W01,W02`. Forecast is strictly read-only: its candidate Proposal/BranchSet/Decision refs and successor State are unpersisted previews, and must be submitted through the normal scheduler path before they can become evidence.
   For a studio UI or deployment scheduler, `world-os serve` exposes the same Brain through a bounded HTTP surface. Keep it on loopback unless a token environment variable is configured; a server-side connector or LLM shadow profile also requires that token, and network dispatch requires explicit `--allow-network`. Register LLM request/policy/provider bindings at startup with `--shadow-profiles` (the bundled `http-shadow-profiles.example.mjs` selects only an enabled exact policy/request pair; network profiles additionally require `--allow-llm-network`); remote JSON may only select profile ids and worlds/budgets, never supply connectors, providers, State or Canon writes. `POST /v1/brain/runs` is dry-run by default, `POST /v1/signals` only accepts receipt-bound privacy-bounded observations, and all writes are serialized per server.
7. Never label `simulation.main` as Canon. A candidate fact, Hard Lock change or irreversible event requires a human approval on an exact version.
8. Read the Outbox only after a terminal EventCommit exists. `world-os dispatch` is dry-run by default and records claim/attempt evidence; invoke a real MCP tool only when its installed server, tool contract, account and audience are known and the connector is explicitly approved. The bundled stdio adapter uses `shell:false`; the HTTP adapter uses bounded JSON/SSE and environment-only credentials; both require `trusted=true` and deployment configuration.
9. Send only the projection payload, exact source refs and idempotency key to MCP. Record the response as a PublishReceipt through Codex.
10. Platform feedback may enter only through `signal-ingest` or the equivalent authenticated `/v1/signals` route as a successful-receipt-bound, privacy-bounded `ExternalSignal`. Use `signal-use` or `/v1/signal-uses` to record whether Codex used, deferred or dismissed that exact signal. It remains observation-only proposal input; never fabricate feedback or let platform state overwrite WorldState or Canon.

After an interruption, run `world-os audit`. Staging states and decisions are evidence, not authority; do not delete them. Retry the deterministic proposal or use `recover` to rebuild projections. Only the terminal commit chain defines the stream head.

Future LLM API adapters are candidate generators. They must return `world_os_event_proposal` with `source.authority=proposal_only`; they cannot approve, commit or write state. The OpenAI-compatible adapter is opt-in only, requires explicit trust and `--allow-network`, bounds request/response bytes, and records usage without retaining raw output or hidden reasoning.

Do not claim that a real platform, model provider, media generator, rights review or human Canon approval ran unless corresponding evidence exists.
