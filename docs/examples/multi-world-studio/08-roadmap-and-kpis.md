# 90 天路线与指标

状态：`draft v0.1`
目标：在 90 天内证明“一个主世界可连续生产、第二世界可被孵化、World OS 可复用”，而不是同时完成四个世界的商业化。

## 0. 截至 2026-08-24 的真实进度

- 第 1–14 天的文档底座和 World OS Decision Cycle v0.4 已完成开发验证：Codex 预写目录可驱动 W01 连续推进 3 步，W02 可推进安全基线后停在阈值 Gate；GateRequest/GateDecision、精确 resume、Canon promotion、ContinuityLedger、缺模板 work item、observation-only ExternalSignal 和 weighted-fair Portfolio receipt 已在本地实现。
- ActionCatalog、EventTemplateCatalog、BranchSet、延迟后果、RunReceipt、候选隔离、审计与恢复夹具已实现。
- Gate A 只能标记为“机器结构通过／人类审批仍 pending”；不得把测试通过等同于世界 Canon 获批。
- 第 15–90 天涉及 CharacterSpec、SceneSpec、StylePackage、Rights、人类评审、真实发布和受众数据的交付物均未执行。
- 下一技术里程碑的本地控制面已推进到 `Codex Brain`：有界 preflight → Portfolio → proposal-only LLM shadow → MCP dry-run/opt-in → postflight 收据；stdio 与 HTTP/Streamable-HTTP connector、直接 OpenAI-compatible provider 入口、loopback/Bearer-auth HTTP Brain 控制面，以及 ProductionSlice → fixture ExecutionReceipt → Draft MediaImport → human QA Review → private ApprovedAsset/ReleaseReceipt 桥均已完成本地验证。真实 server、账号、模型、billing、真实供应商媒体执行、多人审批与公开 Release 证据仍未执行。

## 1. 第 1–14 天：建立底座

### 交付物

- Meta Bible v0.1 与母品牌连接规则。
- 四张 World Card 与世界立项评分。
- W01 World Bible v0.1。
- W02 World Bible v0.1。
- Canon、State、Event 与 Continuity 模板。
- 统一 ID、版本、锁级、审批与权利字段。
- 资产与生产流程图。

### Gate A

- W01 和 W02 的观众承诺能否用一句话区分？
- 每个世界是否至少有三条带成本与例外的规则？
- 是否存在日常系统，而不只有宏大设定？
- 角色、场景、风格是否有明确所有者？
- 未决定内容是否保持 `undefined` 而非被补成事实？

不通过时继续设计，不进入批量生成。

## 2. 第 15–30 天：W01 最小可发布系统

### 交付物

- 沈蘅、顾行舟及两名支点角色的 CharacterSpec 草案。
- 人工选择后的中性身份/身体参考计划；不得声称已生成或已锁定。
- 鹤鸣巷总平面与 5 个英雄地点 SceneSpec 草案。
- W01 StylePackage 探索方向与验证夹具。
- 首季 StoryBrief 与 8 个因果节拍。
- 10–15 个候选内容 Brief，覆盖人物、器物、日常、微悬疑和主线。
- 一支 60–180 秒试播微剧情的完整生产计划。

### Gate B

- 角色在不依赖服装和发型时是否仍有可辨身份锚点？
- 五个地点是否有稳定方向、入口、路径和尺度？
- 首季每个节拍是否由主角选择导致下一节拍？
- 风格是否能排除通用古偶与仙侠漂移？
- 每个必要参考和外部依赖是否有权利状态？

## 3. 第 31–60 天：形成连续生产

### 交付物

- W01 经过审核的角色、场景与风格版本。
- 3 个可连续观看的微剧情或等量的验证单元。
- 一组日/夜、晴/雨、日常/危险的场景状态资产。
- CharacterBench、SceneBench、StoryboardBench 与 RightsBench 初版。
- 发布与学习日志连续运行至少 3 个周期。
- W02 的一种角色/场景固定夹具与 3–4 个单轴风格候选。

### Gate C

- W01 是否能在不重建全部资产的情况下持续产出？
- 角色、地点和风格失败是否能定位到一个责任域？
- 已通过的任务是否在修复时保持不变？
- 观众是否能复述至少一个人物欲望、关系或未解问题？
- 团队是否能解释每项发布素材的权利与版本来源？

## 4. 第 61–90 天：验证双世界能力

### 交付物

- W01 一个试播小季或等价的完整因果闭环。
- W01 的可复用角色、场景、器物、声音与风格资产目录。
- W02 一个概念预告生产包、一个生物/生态档案栏目样本和一个勘界事件样本。
- W01/W02 的视觉与声音差异审核。
- W03/W04 只保留 World Card、差异性判断和低成本试验结果。
- 第 91–180 天投资决策：加码 W01、提升 W02，或暂停某个候选世界。

### Gate D

- 两个世界不看标题时是否仍能被视觉和叙事识别？
- W02 的巨构机制是否产生角色选择，而非只制造景观？
- World OS 是否能复用而不复制 W01 的审美？
- 主世界产能是否因孵化第二世界而显著失稳？
- 是否有足够证据决定下一阶段，而非只凭主创兴奋度？

## 5. KPI 体系

### 创意与叙事

| 指标 | 定义 | 观察方式 |
| --- | --- | --- |
| 世界辨识度 | 不看标题能识别世界 | 盲测、评论语言、封面混排测试 |
| 角色记忆度 | 观众主动说出名字、目标或关系 | 评论、搜索、复述测试 |
| 因果完整度 | 节拍含目标、阻碍、选择、变化和下一因 | Story QA |
| 世界规则利用率 | 规则是否实际迫使角色付代价 | 剧情审阅，不按设定出现次数计算 |
| 伏笔回收状态 | setup/payoff 是否有精确状态 | ContinuityLedger |

### 连续性与质量

| 指标 | 定义 |
| --- | --- |
| Character blocking pass | 身份、比例、惯用侧等阻断项全部通过 |
| Scene blocking pass | 地理、入口、尺度、物理光等阻断项全部通过 |
| Rights blocking pass | 必需资产、肖像和依赖的使用范围明确 |
| 单变量修复率 | 修复是否只改变失败责任域 |
| 未知诚实度 | 缺证据项保留 unknown，而不是伪装成 PASS |

阻断项要求全通过；不得用平均分掩盖身份、地理或权利失败。

### 生产效率

- 每个批准资产的候选次数与人工时。
- 已批准资产复用次数。
- 因上游版本变化而重新审核的比例。
- 失败格单独重试率与全量重做率。
- 从 Brief 到 Release 的周期。
- 每个世界的活跃资产数、过期资产数和孤立资产数。

### 受众与内容

- 回访与连续观看，而非单条偶发播放。
- 收藏、分享、角色名提及、关系讨论和理论推测。
- 观众是否使用世界内部词汇。
- 从世界切片进入微剧情、从微剧情进入连续内容的转化。
- 共创提案的质量；高数量不等于高 Canon 价值。

## 6. 世界立项评分门

每项 1–5 分，任何一项低于 3 都不进入重资产生产：

| 维度 | 核心问题 |
| --- | --- |
| 一句话差异 | 观众能否立即理解它与现有世界不同？ |
| 人物压力 | 世界规则能否迫使人物做艰难选择？ |
| 日常密度 | 不依赖主线时是否仍有可看的生活？ |
| 资产复用 | 角色、地点、物件是否能支撑多种内容？ |
| 视觉独立 | 色彩、材料、尺度、运动是否明显独立？ |
| 内容续航 | 是否能自然产生至少 30 个内容 Brief？ |
| 生产可行 | 当前团队能否用可控成本验证？ |
| 权利可解 | 关键参考、肖像与商业使用能否合规解决？ |

总分只用于比较，不能抵消某一项的阻断失败。

## 7. 预算框架

本方案不预设具体金额。预算按以下桶管理：

- 世界与剧本开发。
- 角色/场景/风格探索与人工评审。
- 生成、编辑、声音与确定性组装。
- 数据、存储、版本和备份。
- 权利、法律与专家审阅。
- 发布、社群与合作。
- 10–15% 探索与失败缓冲。

每项外部执行应有尝试次数、成本上限和失败停止条件。失败重试会计入预算，不能在收据中消失。

## 8. 第 90 天决策

只允许以下四种结论：

- `scale-w01`：W01 已形成复用与连续观看，扩大主世界。
- `promote-w02`：W02 的人物与生态机制成立，增加孵化资源。
- `repair-system`：内容有兴趣但一致性或产能不足，优先修 World OS。
- `pause-world`：某世界差异、续航、权利或成本不成立，保留文档但停止生产。

不得因已经投入时间而自动继续，也不得因一条爆款自动把候选设定写入正史。
