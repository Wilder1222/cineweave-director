# 多世界 AIGC 工作室运营模型

状态：`draft v0.1`

## 1. 运营原则

1. 世界是长期产品，单条内容是世界状态的一次可见切片。
2. 一个主世界进入稳定生产后，第二世界才进入高成本制作。
3. Codex 是系统的唯一编排大脑和权威写入者；创作者批准 Canon，外部 LLM、MCP 与平台都不能直接写世界状态。
4. 所有发布内容都能回溯到精确角色、场景、风格、事件和权利状态。
5. 资产制作过程可以发布，但应使用世界内叙述而非工具日志包装。

## 2. 最小团队

早期可由 1–3 人承担三种人类责任：

| 人类责任 | 最终决定 |
| --- | --- |
| 创意总监 / Canon Owner | 母题、世界立项、铁律、不可逆事件、角色与风格锁定 |
| 视觉技术负责人 | 资产结构、参考策略、生成能力、质量门和交付标准 |
| 制片与运营负责人 | 排期、预算、发布、数据复盘、权利档案与合作边界 |

以下名称是同一个 Codex 编排器内部的领域审阅 pass，不是彼此争夺状态写权限的自治剧情 Agent：

- Intake/Router：把请求拆成有依赖的任务图。
- World Architect：维护世界承诺、规则、派系、日常与历史伤口。
- Story：开发戏剧问题、因果节拍、场景变化与连续性。
- Character：维护身份、心理、行为、外观状态和一致性。
- Scene：维护地理、材料、状态、物理光和互动约束。
- Style：维护媒介、表现语法、抽象预算、禁用项和跨媒介绑定。
- Director/Prompt：把批准时刻变成镜头与可执行语言。
- Production/QA：配方、控制、证据、权利、能力、审核和修复。
- Librarian：索引版本、冲突、审批、发布与回收数据。

## 3. 人工审批门

本文件复用 `04-world-template.md` 的语义 Gate ID，避免同一个编号在不同文档代表不同决策。

| Gate ID | 必须回答的问题 | 通过后允许 |
| --- | --- | --- |
| `gate.portfolio-fit` | 这个世界是否符合共同母题、保持独立且资源角色清楚？ | 进入 World Card |
| `gate.world-inception` | 是否有清晰承诺、规则代价、日常系统和可持续引擎？ | 编写 World Bible |
| `gate.rules-canon` | 世界规则、代价、例外和历史边界是否可检验？ | 激活基础世界规则 |
| `gate.character-identity` | 人物身份、行为与权利是否通过独立验证？ | 锁定精确 CharacterSpec |
| `gate.scene-geography` | 英雄地点的地理、尺度与物理是否通过验证？ | 锁定精确 SceneSpec |
| `gate.style-activation` | 风格是否可重复且不会改写身份、地理或 Canon？ | 激活 StylePackage |
| `gate.story-canon` | 人物选择是否因果推进且结算真实代价？ | 把候选事件提升为 Canon |
| `gate.cross-world` | 跨世界事实是否满足稳定世界、双向影响与权利要求？ | 建立精确跨世界连接 |
| `gate.production` | 精确版本、权利、能力、预算和控制是否齐全？ | 执行媒体生成 |
| `gate.release` | 媒体、声音、文案、连续性、权利和 QA 是否通过？ | 对外发布 |

审批必须绑定精确版本；新版本需要重新审批。

## 4. 内容阶梯

```text
资产条目
  ↓
15–45 秒世界切片
  ↓
60–180 秒微剧情
  ↓
3–8 分钟单集
  ↓
季度/季节故事
  ↓
长片、动画、出版、游戏或授权
```

同一资产应服务多个内容层级。例如鹤鸣巷香铺可以产出空间志、器物短片、角色日常、雨夜悬疑和正式剧集，而不是只在一个镜头中消耗掉。

## 5. 母账号与世界栏目

启动期使用一个母品牌账号和统一资产库，通过世界编号、封面系统、片头声音和栏目标签区分内容：

```text
W01 / 人物簿
W01 / 临安今日
W01 / 百香谱
W02 / 山海物种志
W02 / 勘界日志
LAB / 世界实验
```

独立账号拆分条件：

- 一个世界已连续稳定发布至少一个完整周期；
- 观众能够独立识别其角色和视觉；
- 有足够资产支持独立更新，不依赖母账号填充；
- 运营负责人确认不会稀释主世界产能。

## 6. 初始内容配比

以下是测试结构，不是永久算法：

- 40% 世界日常、环境与氛围。
- 20% 人物、器物、生物或职业档案。
- 15% 微悬疑、关系变化和单元事件。
- 10% 连续主线。
- 10% 制作过程、设计选择和质量修复。
- 5% 观众互动与候选方向测试。

每条内容都要回答至少一个问题：这个世界今天增加了什么可理解的事实、关系、情绪或期待？

## 7. 周运行节奏

| 时间 | 工作内容 | 输出 |
| --- | --- | --- |
| 周一 | Canon 与状态同步、上周反馈分拣 | 本周可用事实和候选池 |
| 周二 | Story/Character/Scene/Style 准备 | 精确上游版本与任务 Brief |
| 周三 | 候选生成与独立资产任务 | Candidate 与证据记录 |
| 周四 | QA、单变量修复、版权与连续性检查 | 通过资产与失败清单 |
| 周五 | 编辑、文案、发布审批 | Release 包 |
| 周末 | 发布、互动、观察，不即时改正史 | 数据与观众语言样本 |

低频精品团队可以把一个“周”拉长为两周，但审批顺序不变。

## 8. 观众反馈治理

反馈分为四类：

- `signal`：观众是否理解世界、角色和关系。
- `preference`：更喜欢哪种合法表现方向。
- `idea`：可进入候选池的新人物、地点或事件。
- `canon request`：要求改变正史或配对关系。

前三类可影响探索；第四类必须经过故事与 Canon 门。高赞评论不等于正史决定。

## 9. 资源配置

启动期采用 `70 / 20 / 10`：

- 70%：W01《临安春信》的实际生产与连续发布。
- 20%：W02《山海／天门》的概念、风格和能力验证。
- 10%：World Lab，对 W03/W04 或新媒介做低成本实验。

只有主世界的质量与节奏稳定后，才把第二世界提升到 40% 以上。

## 10. 商业化阶梯

商业化不得早于世界辨识度与权利档案：

1. 内容与社群：建立角色记忆、世界词汇和持续期待。
2. 数字产品：设定集、艺术册、世界地图、音乐、创作过程或会员内容。
3. 轻衍生：经过权利审核的壁纸、卡片、服饰图案、器物联名。
4. 授权合作：品牌短片、展览、出版、音频或互动体验。
5. 长线开发：动画、影视、游戏或线下空间。

不要在身份、风格和权利尚未稳定时批量制造实体衍生品。

## 11. 风险登记册

| 风险 | 早期信号 | 控制措施 |
| --- | --- | --- |
| 世界过多 | 每个世界只有概念图，没有连续内容 | 70/20/10 与世界立项门 |
| AI 通用脸/通用质感 | 换标题后看不出世界差异 | 身份锚点、风格不变量和禁用项 |
| 设定很多但没有戏 | 内容只能介绍百科 | 每次用选择与后果检验规则 |
| 地理与时间漂移 | 门、路、道具、伤势无原因变化 | SceneSpec、State 与连续性账本 |
| 反馈绑架正史 | 临时迎合导致人物弧崩塌 | 候选池与 `gate.story-canon` |
| 版权/肖像风险 | 参考来源或授权范围不清 | 一参考一角色、LicenseProfile、未知即阻断 |
| 供应商锁定 | 创意事实写成某模型参数 | Provider-neutral 合约和适配层 |
| 成本失控 | 大量全量重做 | 小配方、失败任务单独重试、资产复用率追踪 |

## 12. 会议与记录

每周只需要三份权威输出：

1. `Canon Change Log`：本周新增、改变、冲突或拒绝的事实。
2. `Production Board`：任务、上游版本、负责人、Gate 和状态。
3. `Release & Learning Log`：发布版本、数据、观众理解与下一轮假设。

聊天记录、提示词历史和零散灵感均不能替代这三份记录。
