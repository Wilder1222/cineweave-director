**C．Wan 首帧与运动稿的冲突检查**

目前**尚不能证明矛盾**。“右手在身侧”描述手与身体的关系，“已靠近玻璃”描述手与玻璃的关系，两者可能同时成立。“能够够到”也不能证明已经靠近、接触或握住；手可见同样不能证明空手。

执行前，应核对实际图片中的距离、接触、握持和右手占用状态，并确认“玻璃”是可拿起的物件。若指固定窗玻璃，“拿起”本身便不成立。

将符合条件的**实际图片绑定到 Wan 的首帧输入**，不能只在提示词中写“遵循首帧”。例如阿里云 Wan 3.0 API 使用 `input.media` 中的 `type: "first_frame"`；其他版本及界面须分别核对。[Wan 官方首帧说明](https://www.alibabacloud.com/help/en/model-studio/wan3-video-generation-guide)

按实图选择以下局部修订：

| 实图状态 | 遵循首帧的动作写法 |
|---|---|
| 尚未靠近、未接触，右手可抓取 | 从身侧实际位置伸向物件，接触、握稳后再拿起。 |
| 已靠近、未接触，右手可抓取 | 从现有位置短距离靠近，接触、握稳后再拿起。 |
| 已接触但未握稳 | 从已有接触继续，调整手指形成稳定握持，再拿起。 |
| 已握住 | 保持已有握持关系，直接抬起；不重新安排抓取。 |
| 右手另有持物且妨碍抓取 | 先确定原持物的处理方式，不能让它凭空消失。 |

其中，“尚未靠近、未接触、右手可抓取、物件仍有支撑”的条件稿为：

```text
以绑定首帧为初始画面。右手从首帧中身侧的实际位置连续伸向玻璃物件，先接触物件，再合拢手指形成稳定握持，随后将物件抬离原支撑面。物件在被握稳前保持原位，伸手、接触、握稳和抬起依次衔接。
```

如果实际首帧已经靠近，就缩短靠近过程；只有实图确认初态不同，才能将原稿的“一开始已靠近”判为冲突。
