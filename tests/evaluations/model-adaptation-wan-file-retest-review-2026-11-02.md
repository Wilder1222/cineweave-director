## 结论：A、B 作为条件文字方案基本可审；C 的精确编辑模式尚未验证

1. **目标、互斥和替代损失：通过。** 原题要求产品图严格锁首帧、模型读不公开的本地 PDF、末尾精确广告语和 12 秒。复测保留原目标并说明素材、账号和许可尚缺；依据 [中国站 Wan 3.0 API](https://help.aliyun.com/zh/model-studio/wan3-video-generation-api-reference) 将 `first_frame`/`last_frame` 与 `file` 等参考类型同请求互斥限定于此 API。A 明确失去模型读 PDF；B 的图片只是参考并失去原生首帧控制；C 即使后期替首帧，也不等于同一次生成完成全部硬要求，且都未经用户选择。
2. **中国与国际站输入：安全边界通过，但国际站证据可追溯性仍可加强。** 复测已把公网 HTTP(S) 与临时 OSS 说明限定为中国站文档，提醒其他地区不能推定临时 OSS 支持，不得为调用公开内部文件。[中国站 API](https://help.aliyun.com/zh/model-studio/wan3-video-generation-api-reference)对 `file` 列这两类 URL；[国际站 API](https://www.alibabacloud.com/help/en/model-studio/wan3-video-generation-api-reference)目前对 `file` 只列公网 HTTP(S)，对图片列公网和 Base64，并未列临时 OSS。复测未直接链接并逐项写出国际站这一差异，但没有把中国站路径宣称为国际站已验证。国际站文档没列不是证明技术上绝对不存在其他私有方式；保持未知并按实际入口核实。
3. **临时文件与隐私：通过。** [中国站临时上传文档](https://help.aliyun.com/zh/model-studio/get-temporary-file-url)列 48 小时有效、模型与主账号绑定，并提醒不要用于生产环境；同时说明该上传功能列北京和新加坡，具体仍须按目标 API 与账号组合核实。复测未把“不可公开”改写成“绝不允许授权外传”，亦未把临时 URL 称作本地处理；B/C 明确文件传输须授权，A 的产品图传输也须许可。
4. **A 条件稿：基本通过。** 用户图片未知时，以真实图像为起态、生成 12 秒单镜、保持图中可见包装与位置、无生成文字并由授权人员本地核字和后期排版，损失清楚。`first_frame` 单独输入、`duration=12`、`audio=false`、`prompt_extend=false` 符合所引 API 的条件范围；默认画幅及实际结果仍待核。文案、文件和账号未知，不能称已可提交或完成。导演所设计光影与尾部留白要等真实图像检查，不能保证可实现。
5. **B 条件稿：基本通过。** `file` 与 `reference_image` 的组合被中国站 API 的“文件/网页生视频”示例列出；`prompt_extend=true` 也是官方要求。其完整正文不虚构广告语，说明参考图不具首帧锁、文档内容理解和画面准确度需核对。精确广告语改由经授权的本地提取与后期人工核对，并说明智能改写不保证逐字排版；实际资料传输通路和权限未证实。
6. **C 条件稿：存在模式证据缺口，不能判定该请求可用。** 中国站同一 [API 素材组合](https://help.aliyun.com/zh/model-studio/wan3-video-generation-api-reference)的通用规则与“文件/网页生视频”示例列 `file + reference_video`；但“视频编辑”具体组合只列必要的 `reference_video`，可结合 `reference_image` 或 `reference_audio`，没有列 `file`。复测 C 的第二段提示词以“编辑输入的视频”开始，因此不能仅凭通用的文件+视频组合断言精确编辑模式支持带 `file` 的请求。可能的解析/模式行为及实际返回都未知；应先核实模式的官方证据，或将其明确改作文件参考视频生成的条件探索并说明并不保证编辑语义、首帧或原视频一致。不能因此断言该组合必然失败。12 秒输入参考视频加 12 秒输出为 24 秒，落在文档总时长上限范围内；输入视频格式、帧率及 ≤15 秒等各项限制、区域与服务开放仍须核验。
