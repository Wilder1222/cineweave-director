# 工作模型

CineWeave 导演是总入口与导演核心；内部路由保持领域权威，已启用的专业 Skill 负责限定交付。各安装包自包含，共享规则只有一个维护源；同代理按需读取与独立子代理执行分别记录，不用入口数量暗示已执行多代理调用。

## 中文工作约定

语言、准确文案和提示词交付规则统一见 [Skill 入口](../../SKILL.md#创作约定)。本指南只补充跨阶段的依赖与成熟度管理。

## 任务范围与上下文

延续同一项目／对象时，继承仍适用的用户事实、决定和授权，不重复确认。用户明确指定独立任务、不同项目或独立试跑时，只使用当前输入及明确允许复用的上下文。

前案原创人物、服装、场景、光源、镜头和批准状态不能变成独立案例“已提供”或“已确认”的事实。新假设明确标注，不覆盖待评审目标。只有文件名、摘要或检查通过声明时，说明缺少真实正文／媒体；试片以待提供的原身份、服装、场景、光源和准确声音为待锁输入，不借邻案补证据。

假设、用户事实、正式设定、观察和批准分别保留来源；同一制作可复用对应来源与已委托设计。隔离独立案例无需清空会话或增加逐阶段确认。

## 架构与职责

任务入口、共享设定、专业设计、提示词编译和证据评审是同一 Skill 的职责层。创作方法说明如何选择和表达；平台限制另记模型、界面、模式与查阅时间，不将暂时限制提升为电影规律。

| 职责层 | 读取与产生 | 权威位置 |
| --- | --- | --- |
| 任务入口 | 识别交付、已有材料、用户锁定及起始阶段，选择必要路由 | [Skill 入口](../../SKILL.md)、本工作模型 |
| 共享设定 | 保存故事事实、人物身份／外观、场景空间、表现媒介及光色基线 | [视觉规范与连续性](visual-bible-and-continuity.md)及各领域母稿 |
| 专业设计 | 将意图变成节拍、表演、调度、摄影、声音与剪辑决定，引用共享设定并记录本镜变化 | 既有故事、人物、场景、动作、导演、分镜与制作路由 |
| 提示词编译 | 将设计展开成资产、静帧、运动、配音及声音稿；按实际平台能力另作适配 | [图像提示词](../routes/image-prompt.md)、[全套创作](../optional/short-film-creation.md)、[平台适配](../optional/video-platform-adaptation.md) |
| 证据评审 | 分别检查文字一致性、已返回媒体与采用边界，确定缺陷归属和受影响范围 | [评审与修复](../routes/review-repair.md)、[修订工作表](../optional/drafts-and-change-impact.md#修订工作表与恢复检查点) |

每项决定只有一个维护来源，复制稿是具体镜头中的展开。编译发现动作不可达或表演矛盾时，返回场景或人物等责任领域，再同步消费者；不偷偷重写上游。已授权原创可在相应领域作可撤销设计，无需为每次回流确认。

`contracts.json` 管路由及产物归属，`reference-lifecycle.json` 管分发与加载条件，生成的契约索引管 schema／示例清单；工作流表只导航。跨阶段用[阶段交接](../optional/short-film-creation.md#阶段交接)，单项任务从已有输入进入，完成后结束。

## 路由图

仅使用完成请求所需的最小路由集合：

`简报与世界 → 故事 → 人物／场景／风格／参考证据 → 动作／镜头 → 分镜节奏 → 图像提示词 → 制作计划 → 评审修复`

无关依赖可以跳过。例如，产品静帧可从 `brief_world` 直接进入 `scene`、`style`、`shot_direction`、`image_prompt`；剧本改写可以在 `story` 结束。不能编造跳过环节中缺失的可复用事实。

允许两种起点：

- **故事驱动：**先明确世界设定的权威来源与因果节拍，再进行视觉开发。
- **视觉驱动：**先探索限定范围内的视觉假设，再收敛故事。

两条路径都收敛到明确的戏剧或感知单元和适用视觉规范。草稿使用声明的假设，精确编译沿用确定事实。因果叙事中风格不替代因果；观察或联想创作不强加冲突，非叙事静帧明确传播目标及可见状态即可。剧本不无声地定义人物身份、空间地理或表现媒介。

## 交互深度

- `zero_prompt`：根据空白请求提供少量可开始创作的方向，选定后展开；不预先要求填写完整表格。
- `quick`：采用低影响、可撤销的默认选择，并明确说明。
- `guided`：询问会改变路由、身份、权利、历史处理、时间结构或交付物的必要问题。
- `professional`：用于完整定稿、综合评审或正式交接，维护相关产物关系、锁定、证据与检查。

深度随任务选择，不给普通草稿默认套用专业制作流程；细节充分的完整稿件不依赖关系图、JSON 或工具工作表。`professional-lite` 仅表示简洁呈现必要结论，不是 `inputMode`、路由、执行模式或契约值。

继承适用授权；只有未决答案会使交付失效时才询问，否则声明假设并完成本次工作。

## 阶段纪律

跨阶段交接说明输入、输出及影响下游的未决事项；只有确有后续工作时列下一步。单项完成即可结束，不为每次创作列关卡或等待确认。

缺少必要输入只阻止依赖它的最终确认；独立工作和标注假设的草稿继续。完整项目保持逐项可用稿件，不压成一条巨型提示词。

## 创作成熟度与授权决策

成熟度属于工作流指导，不是新的 `inputMode`，也不替代现有契约状态枚举。

- **探索：**提出原创假设、比较方向。标注清楚后可以比较多维概念；要做因果对比时使用单变量变体。
- **草稿：**将已声明假设带入完整、可审阅的交付物。暂定选择不能表述为已批准的正式设定。
- **定稿：**保持用户事实与已委托决定一致；只对未授权且会使交付失效的重大选择取得确认，不重复确认已明确的创作授权。

用户确认的事实、已委托的可撤销决定、暂定假设和实际观察分别保留来源，不互相改记。记录授权、硬锁及用户保留的决定；已有适用授权不再询问，完整概念请求允许可撤销草拟，不批准素材权利或外部执行。先完成草稿，再集中列出重大未决选择；它们只阻止依赖该选择的定稿。

需要非规范工作稿 JSON、版本提升或恢复项目时，阅读[草稿与变更影响](../optional/drafts-and-change-impact.md)。

## 能力交接与迁移

工作流统一从导演入口接收请求，单项与多阶段任务都只组织本次需要的能力；内部 Skill 返回限定结果，导演核对原请求后统一交付。领域／产物的实现归属不等于工作流最终负责人，后者始终是本次导演入口。实施中的开发目录将目标归属与实际启用区分：未启用的专业能力不能被表述为已安装或已调用。正式设定及领域路由的权威不因入口拆分改变。

交接保留原请求、当前子目标、准确源正文／可访问素材、硬锁、已委托决定、假设和未知项；说明本能力允许修改的产物及不允许改变的上游事实。返回完整稿件、实际发现、待补依赖、修订范围和后续责任。规范交接逐字继承已有 kind、ID、版本、哈希；缺规范身份的工作稿保持工作引用，不填假 ID 或批准。

依赖的创作步骤串行。冻结输入上的独立研究或检查可以并行，只返回限定结果，由总负责人按领域归属整合一个选定版本；同一共享人物、场景或镜头不并行改写。发现上游问题返回责任领域，新版本发布后复查受影响消费者。

同一代理按需读取并执行内部 Skill 是默认路径，子结果都返回导演入口；内部能力不能跳过最终原请求检查。缺专业能力时，导演使用仍可用的内联路径并说明实际交付范围，不要求用户换入口、不伪称调用或自动安装。独立审阅仅在真实独立执行时如此记录，多视角不要求多代理。专业能力、研究、结构检查和编排均不扩大外部执行授权或媒体验收结论。

## 规划边界

本 Skill 编写和评审创作产物，不调用供应商、不运行适配器、不安装模型、不写入生成媒体、不批准素材权利，也不宣称计划结果已经存在。`PromptProjectionPlan`、`RenderPlan`、能力匹配、画布装配、剪辑和调色产物都只是供外部工作流使用的计划。

平台适配方案必须绑定精确的提示词母稿和能力证据，列出模型／界面默认值及兼容性未知项，并止于人工交接。宣称执行已核验时，必须有实际返回的准确元数据和文件。即使元数据缺失，也可以对可访问媒体开展限定范围的视觉或听觉评审，但缺失内容必须标为未知。
