# 可选参考：阶段产物包与验收

完整短片、短剧、多阶段制作或用户检查阶段交付完整性时加载。单项任务只交付其适用项，不强迫走完 G0–G7。阶段编号是工作表导航，不是新增路由、规范 kind 或运行时状态。

## 完成的判定

本页维护产物内容和验收范围；[场次工作法](scene-directing-pipeline.md#cineweave-阶段结果产物清单-v1没有文件不算完成)维护文件与视觉图卡的就绪关卡，两者须同时满足。完整阶段中的风格、配色、材质、灯光、光位和测试设计板需实际绘制为可打开的 SVG／HTML／PNG／PDF 等；测试设计板可暂缺真实样片，但必须有完整测试稿、固定项、判据和明确的未提供状态。没有文件输出能力时仍交完整正文，明确“图卡未绘制”，不得标 design_ready。

每个适用阶段交付一个主产物包和一份验收表。只有阶段名称、方法说明、空模板、文件名列表或“后续补齐”，不算结果产物。表格、图示、完整提示词可以作为设计产物；它们不能充当真实测试图、音视频或试剪。

每项登记：工作 ID、修订号、用途、实际正文位置（文件或消息内准确章节）、上游 ID／修订、设计状态、媒体状态、验收依据、下游使用者和缺口。正文可以合并在一个文件的独立章节，避免为了编号重复内容。工作 ID 不是规范契约引用；需要规范输出时使用已有 schema，不虚构版本哈希或回执。

工作表分开记录：

| 轴 | 可用工作标签 | 何时可判定 |
| --- | --- | --- |
| 设计 | 未交付／待审／通过／需修订／不适用 | 正文真实存在，覆盖本次需求，完成对应文字或图示检查；不适用须写理由 |
| 媒体 | 未提供／待审／通过／失败／不适用 | 有可访问的准确素材和实际观察才判断；测试任务单只能记未提供 |
| 试剪 | 未提供／待审／通过／失败／不适用 | 有序列和采用区间，实际检查衔接、节奏和声音才判断 |
| 用户选择 | 未确认／已选择／未采用 | 只根据实际反馈或既有委托记录，不由技术检查自动填入 |

这些中文工作标签不扩展 `CreativeReview` 等规范枚举。**阶段完成 = 本次范围所需产物齐备且对应验收通过。**明确区分“设计包已交付”“设计验收通过”“媒体验收通过”“试剪通过”“最终交付通过”。需要媒体的阶段不能用设计通过替代。暂缺媒体时可以继续不依赖它的下游草稿，携带未验证状态；不得宣称正式通过关卡。已授权设计不增加逐阶段人工审批。

## G0–G7 交付表

| 阶段 | 主产物包 | 验收表的必要检查 | 下游交接 |
| --- | --- | --- | --- |
| G0 故事与导演意图 | 故事卡、场次卡、节拍表、完整场次剧本、导演意图卡 | 场次目的、可见行为、因果／观察结构、准确对白、观众信息变化；保留用户限制 | G1–G4 引用场次、节拍与导演意图 |
| G1 视觉开发 | 风格卡、配色卡、材质卡、灯光卡、光位图、LookDev 测试板或完整待执行测试包 | 六项分别有正文；空间与光源一致；测试范围、固定项、差异、媒体状态明确 | G2–G5 共用同一视觉基线和允许变体；G6 接收测试任务 |
| G2 场景空间 | 结构图、方位图、机位可达图、道具位置图、世界光源绑定图、场景状态卡 | 可合为一张带图例平面图与状态表；出入口、人物区、机位区、遮挡、固定锚点可定位 | G3／G4 引用具体方位和锚点，反打不翻转世界位置 |
| G3 调度与表演 | 角色目标卡、表演动作卡、走位图、视线关系图、持物／接触表、硬锁节点表 | 谁触发谁、看向何处、接触可达、动作相位、承接状态；无接触时显式记不适用 | G4 继承动作与反应，不能为机位重置动作 |
| G4 分镜与摄影 | 分镜卡、逐镜镜头表、镜头语言／构图／焦点卡、覆盖表、所需首帧稿和逐镜视频稿 | 每镜目的、景别、轴线、运镜、焦点、时长、表演、光、声、出入点；所有复制稿完整 | G5 继承镜号和边界；G6 接收实际所选生成路径的稿件 |
| G5 剪辑声音连续性 | 节奏表、镜间衔接表、连续性表、声音设计卡、对白表演指导卡、字幕表、调色意图卡 | 切点理由、采用窗口、声音桥、准确台词／字幕、光色连续性、技术输出未知项 | G6／G7 引用镜号、窗口、调色卡和源素材状态 |
| G6 生成测试试片 | 测试任务单、高风险测试组、外部返回的批次记录、候选池、问题样片索引、试剪清单、采用窗口说明 | 任务与返回能对应；实际文件可访问；保留失败、无返回和拒用候选；无素材不编造批次 | G7 接收准确候选和采用区间；本 Skill 只计划／读取证据，不代为生成 |
| G7 审阅修复 | 逐镜审阅表、问题归因表、修复卡、返工任务单、版本差异、通过／未通过清单、阶段报告 | 观察有证据，保留通过维度；修复后需新证据；设计／媒体／试剪／最终状态分列 | 将准确修订交回原归属领域；最终结论覆盖真实声明范围 |

“首帧稿”随实际输入路径适用；文生视频不机械索要首尾帧，无对白无字幕的任务可说明不适用。单独风格卡请求不自动扩成完整 G1；用户明确要完整视觉开发时六项必须齐全。

## G1 六类结果的内容要求

| 产物 | 必须能审阅的内容 | 不合格替代 |
| --- | --- | --- |
| 风格卡 | 表现媒介、叙事用途、形体／边缘／表面／色光／时间规则、硬锁、禁用、适用范围 | “高级、电影感、某导演风格” |
| 配色卡 | 主／辅／强调／中性色的角色、使用对象、面积关系；昼夜或场次变体；色值的色域／显示含义 | 只有五个 HEX，没有用途；把色板称作 LUT |
| 材质卡 | 需要的皮肤、衣料、木石金属玻璃等；基色与反光区别；粗糙／光滑、纹理尺度、冷暖光响应、保留项 | 全部写“真实细腻”，以颗粒冒充织纹 |
| 灯光卡 | 世界光源 ID 与动机、主辅与轮廓关系、软硬／方向／明暗层次、允许补光、曝光意图 | 只有“电影柔光”，无来源与面部体积 |
| 光位图 | 可读俯视图或示意图、方位和图例、源光／人物／遮挡／摄影机位置；注明尺度是否为设计假设 | 一句“左冷右暖”，与空间图不一致 |
| LookDev 测试板／测试包 | 人物近景、场景空镜、材质、内外光转换、反打一致性；每项有完整输入／提示词、固定变量、判据、文件／返回状态 | “待生成五张图”，空白格冒充测试板 |

测试板含真实媒体时逐格登记准确素材和观察。无媒体则交付完整测试包并明确标“待执行”，G1 只能完成设计交付与文字检查，视觉一致性仍待审。图示是布局设计，不是真实照度测量。

## 可复制的验收记录

每个阶段一张表，至少包含：`产物 ID@修订 | 实际正文位置 | 上游引用 | 设计状态及依据 | 媒体状态及依据 | 下游 | 缺口`。使用 `G1_STYLE_001@r1` 等可读工作 ID；不根据编号臆造文件。修改配色、材质或灯光后，检查消费它们的分镜、提示词、调色卡与测试任务，撤回旧版本相应通过状态。

验收表必须列出每个适用必交项，缺失项保留为未交付。合并卡片只减少文件数，不减少检查项。总结报告给出确实完成的范围、仍缺的证据和下一步依赖，不能只给“总体通过”。

完整 G1 设计示例见[视觉开发交付样例](lookdev-delivery-example.md)。调色卡按[预设调色库](color-grading-presets.md)编制，不能代替其余五类视觉开发产物。
