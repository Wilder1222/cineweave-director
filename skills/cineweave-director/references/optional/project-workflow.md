# 跨集项目、资产引用与镜头回流

多集短剧、同一角色跨时期／多套造型、跨场次共享素材，或恢复已有制作项目时按需读取。单图、单段改写和现成母稿忠实适配不要求建立项目表。本页是既有产物的查阅与交接方法，不新增事实权威、根契约、项目存储或生成执行入口。

## 一份项目总览，按本次范围展开

先继承现有设定和已完成正文，明确作品总清单、本次集／场范围与剩余项。创作方向、分集大纲、完整正文分别定位；已有正文可直接从相应阶段继续，不因补索引要求重写或重复批准。单集可按场次推进，多集不必机械各建一套独立设定。

| 查阅层 | 保留的信息 | 避免的误判 |
| --- | --- | --- |
| 项目 | 全部已声明集号、当前工作范围、共享设定位置、仍待展开项 | 两集样例不是全剧完成；未定总集数不编造总量 |
| 每集 | 本集任务／观察对象、设定／大纲／正文的准确位置和修订、场次顺序、进入／退出状态、未决与下一步 | 不从文件名或标题推断正式集号、剧本已审或镜头数量 |
| 每场 | 归属集、完整正文、人物／地点、场次任务、知情／持物／伤情／关系等实际变化、所需镜号 | 叙事时间与展示顺序分别记录；无镜号的正文不冒充已拆镜 |
| 每镜 | 原镜号、所属场次、母稿修订、所用身份／造型／场景版本、准确对白、预演与候选位置 | 一个镜头有完整内容后才列完成，不能用数量或空卡代替 |

每集退出与下一集进入不一致时，先说明时间省略、时期变化或尚待设计的接口，依[故事连续性](../routes/story.md#连续性)核对。集尾钩子取决于作品意图，日常观察作品不被强加悬念。跨集人物知识、道具、伤情与伏笔仍由原正文和连续性记录持有，索引只引用。

## 角色身份、时期和造型适用范围

复用 `CharacterSpec`、已有 `age_state` 变量、`CharacterAppearanceState` 和 `CharacterBinding`，不另造“时期人物”根产物。时期表是叙事适用范围索引：同一稳定身份可以有少年／成年、不同妆造与伤情状态，变化必须在用户允许的年龄／身份范围内，并保留该时期可辨识的身份锚点。服装、发型或同名不能独自证明跨年龄身份。

每种实际使用状态至少能回答：**谁 → 哪个时期／年龄依据 → 哪份外观修订 → 哪些集／场／镜适用 → 从何处开始改变 → 哪些身份特征保持**。同一场内换装或伤情变化优先用准确镜号限定，不能只写“全场适用”。回忆镜的叙事时期不能从集号大小推断。

同一镜头内部脱雨披、卸下配饰等变化，保留唯一角色起态绑定，再用有序 `appearanceChanges` 记录目标外观与可见触发。起态和目标外观均属于同一角色／时期，实际消费的两份资产都保留准确修订；脱下的雨披仍可能作为持有道具存在。不能靠重复角色绑定或同时引用多套衣服来暗示变化已经设计清楚。

| 记录 | 内容责任 | 使用方式 |
| --- | --- | --- |
| 稳定身份 | 原人物母稿与身份依据 | 所有造型引用同一准确身份，无法证明的跨年龄外观仍待检 |
| 时期／年龄 | 正文事件与已允许的年龄状态 | 逐集／场指定适用；倒叙可使用较早时期 |
| 外观／声音 | 指定造型修订、临时状态，相关时带独立声线来源 | 一套外观不暗中改写性格、语言或永久声线 |
| 镜头绑定 | 角色、时期、外观、镜号与参考职责 | 精确绑定；不存在或不适用的状态先修原责任源 |

普通草稿使用可读工作 ID 与本地修订号即可；系统需要正式交接时再绑定已有规范引用。`AssetAliasRegistry` 的精确引用与范围仍有效，不把表中的名称或 `@角色` 当成已经上传、绑定或可自动解析的素材。

## 从镜头消费关系派生资产反查

一份资产保留自己的准确来源、修订和用途；镜头只声明本镜实际消费的资产及职责。身份图、妆造图、空间图、构图白模、动作参考、声音参考各自说明作用，不因使用同一图片就合并权威。探索图只有经用户选择或既有委托选用后，才作为选定引用；生成返回不能自动替代选定资产。

**资产 → 镜号反查由镜头的消费记录推导。**不要同时手填另一份全局使用清单。点击或查询资产应返回集／场／镜及输入版本；反向查镜头应返回同一组准确引用和原稿位置。未声明消费关系不能推断为不受影响，应列依赖待核。

共享资产变化时复用[变更影响查询](drafts-and-change-impact.md#只读变更影响查询)：先列确实受影响的消费项、可保留项与未知依赖，再由所属领域修订。索引检查不自动修改母稿、重拍、换候选或批准新版本。输入旧修订仍可保留为历史依据，但当前交接明确标过期，不能静默指向“最新”。

## 整组预演保留原镜号

对反打、多人互动、连续接触、追逐或复杂机位，选足以检验空间和行动的一组原镜头。先确认完整镜头母稿与组内职责，再制作分镜图／白模／动态参考；按实际平台能力选择整组或分项实施，不固定镜数、素材上限或生成方式。

交接至少保留：组 ID、场次及版本、按成片顺序的原镜号、每格／每段对应镜号、输入资产修订和职责、相邻动作／视线／持物接口、预演实际返回位置或未提供状态。图板排布顺序不替代成片顺序；一镜多格要说明采样时刻，拆格或局部重做后仍回到原镜号。

预演检查分两层：**图内**看构图、关键接触与遮挡是否可读；**组内**看空间轴线、眼线、持物、光源和行动阶段能否承接。预演图通过不证明真实视频的运动、口型、声音或试剪通过。首尾帧承接按用途使用，不把所有反打变成上一镜尾帧的形变延续。

需要数值空间／摄影机控制时转到[外部三维预演交接](camera-previsualization.md#外部工具交接与返回工作单)，继续复用 `SceneBinding`、`ShotSpec`、`CameraPrevisSpec`；预演帧负责构图／运动，角色图负责身份，不能互相替代。

## 候选回到同一镜号

沿用[制作规划](../routes/production-plan.md#生产批次与成片顺序)的“批次 → 镜号 → 源采用区间”关系，将每个外部返回放回原镜头记录。至少带：原镜号、输入母稿和资产版本、真实返回位置或未提供、相关实际任务标识、当前观察问题、保留区间、采用理由与接入／接出复验。没有真实任务时不编造标识，只有链接或路径也不证明媒体可访问。

| 当前材料 | 可报告什么 | 继续所需证据 |
| --- | --- | --- |
| 只有稿件／计划 | 已完成的设计和待制作范围 | 真实候选与准确来源 |
| 已返回候选 | 已声明或实际读到的返回；尚未核验的维度 | 看／听对应媒体，记录实际观察位置 |
| 已选定候选区间 | 用户选择或委托选择的范围和理由 | 镜内及相邻接点复验，真实声画与时长 |
| 小样组可看 | 已组织的镜头和采用窗口 | 观看整组的叙事、动作、节奏、声音和缺失覆盖 |

输入变更使相关候选的旧验收过期，但保留旧记录和已经通过的无关区间。试剪消费来源区间，不能只凭候选总时长拼接。所有窗口声明自己的帧率及端点约定；本页示范检查工作表使用 `[startFrame, endFrame)`，不能混用包含尾帧的契约区间。

## 可选只读工作表

希望核对集／场／镜引用、时期／造型适用范围、资产反查、预演映射与候选输入时，可使用 `cineweave-project-workflow/v1` 工作表：

```powershell
node skills/cineweave-director/scripts/check-delivery.mjs --project-workflow project-workflow.json
```

工作表只收已声明的索引，不解析小说正文、文件标题或媒体来补业务关系；它不是新的根契约。检查结果中的未展开集、过期输入、未返回预演或候选保留为待审／剩余，不能据 `valid` 宣布作品完成。检查器不读取素材、不探测本地／远程文件、不联网、不选用或写回，`mediaVerified` 和 `sourceAuthorityVerified` 始终为 false。全文因果、跨年龄可辨识性、视觉与声音仍需人工及实际媒体验收。

### JSON 字段与退出状态

机器 ID 使用字母起头、只含字母数字及 `._-` 的可读工作标识；中文名称和正文保留在对应文本字段。修订为正安全整数，窗口为帧率下的整数半开区间。以下字段只描述索引，正式产物引用仍沿用原契约。

| 字段 | 形状与责任 |
| --- | --- |
| `format / canonical / projectId` | 固定格式、`false`、本项目工作 ID |
| `frameRate` | `{numerator, denominator}` 正整数有理数帧率；适用于候选窗口声明 |
| `declaredEpisodeIds` | 全部已声明集号的有序清单；未展开集仍保留 |
| `episodes` | 本次已展开集，每项有 `id / purpose / entryState / exitState / source:{path,revision} / scenes`；`scenes` 每项为 `{id,shotIds}`，沿原展示顺序 |
| `characters` | `{id,identityAssetId,periods:[{id,episodeIds}]}`；时期适用集明确，不按集号推断年龄 |
| `appearances` | `{id,characterId,periodId,episodeIds}`，可用 `sceneIds / shotIds` 收窄；`id` 同时是对应外观资产 ID，修订只在资产表维护 |
| `assets` | `{id,revision,role}`；职责为 `identity / appearance / scene / prop / style / reference`，声音、动作等参考使用 `reference`，具体职责仍写在原交接稿 |
| `shots` | `{id,revision,episodeId,sceneId,characters,assets}`；角色起态绑定为 `{characterId,periodId,appearanceId}`，可选 `appearanceChanges:[{appearanceId,trigger}]` 按顺序记录有因变化；资产消费为 `{assetId,revision}`，包含身份、起态及全部目标外观 |
| `previsGroups` | `{id,shotIds,frames:[{frameId,shotId}],status,media}`；状态为 `planned / returned`，无媒体填 `null`，返回定位为 `{locator}`；同镜多格须连续，组内原镜顺序不变 |
| `candidates` | `{id,shotId,inputRevision,assetInputs,media,adopted,adoptedWindow}`；输入为准确资产消费；媒体为 `null` 或 `{locator,totalFrames}`；采用声明与 `{startFrame,endFrame}` 同时保留，未采用的窗口为 `null` |
| `claims` | `{allEpisodesExpanded,mediaComplete:false}`；没有展开全部集不能声称前者为 true；后者不能由本工具确认 |

尚没有角色、资产、预演或候选时，相应数组可为空；不要为凑字段虚构内容。最小可用形状如下，只有一镜的结构声明，尚无媒体：

```json
{
  "format": "cineweave-project-workflow/v1", "canonical": false,
  "projectId": "river-letter", "frameRate": {"numerator": 24, "denominator": 1},
  "declaredEpisodeIds": ["E01", "E02"],
  "episodes": [{
    "id": "E01", "purpose": "展示渡口的营业日常",
    "entryState": "柜台空着", "exitState": "店主已开始整理柜台",
    "source": {"path": "drafts/E01.md", "revision": 1},
    "scenes": [{"id": "E01-A", "shotIds": ["S01"]}]
  }],
  "characters": [], "appearances": [], "assets": [],
  "shots": [{"id": "S01", "revision": 1, "episodeId": "E01", "sceneId": "E01-A", "characters": [], "assets": []}],
  "previsGroups": [], "candidates": [],
  "claims": {"allEpisodesExpanded": false, "mediaComplete": false}
}
```

此最小工作表不声称人物细节或正文完整，`source.path` 只是调用方定位，工具不打开该文件。退出码 `0` 表示索引结构通过且没有本工具识别的待审项，`1` 表示输入错误或结构矛盾，`2` 表示结构通过但仍有未展开／待审／未提供媒体。即使退出 `0`，来源与媒体也未被验证。
