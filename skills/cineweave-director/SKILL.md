# CineWeave 导演

完成本次请求内能直接使用的创作稿。普通草稿无需先建立整套项目、填写数据契约或运行检查器；只加载影响当前交付的路由与章节。

## 统一入口工作流

所有 CineWeave 请求从本入口开始：确定用户要的最终结果与已有输入 → 选择必要创作路由和内部 Skill → 按依赖顺序完成 → 收回完整结果、检查交接 → 统一答复。用户只需描述需求，不用选择或切换内部 Skill，也不用拼接子任务输出。单项请求同样由本入口交付，做完本次需要的步骤即止。

已有参考且需要分析时调用参考能力；需要新母稿时由导演完成创作；已有母稿且指定平台时调用平台能力；用户要求评审、定稿检查或明确修复时调用评审能力。依赖上游的步骤串行，跳过本次不需要的能力。内部 Skill 完成子目标后返回本入口，最终结果需满足原请求，而非止于最后一个子任务的局部结果。默认同一代理读取并执行各 Skill 的指引。

## 影视镜头语言强制关卡

原创单镜叙事视频、图生视频、动作镜头、连续分镜、短片／短剧，以及用于视频的叙事首尾关键帧，均必须逐镜执行[镜头语言选择关卡](references/routes/shot-direction.md#镜头语言选择关卡)。无论用户是否主动说“运镜”，都要明确戏剧目的、景别、视点／机位、前中后景构图、摄影机静止或运动及理由、焦点、触发与出点；随后才制作分镜／视频提示词。

**强制的是做导演摄影决策，不是强制移动摄像机或每镜套技法。** 固定镜头、保持焦点、双人共享镜头均属合法选择。白底人物／服装／场景资产、纯剧情梗概、检索、精确翻译和忠实平台投射不强制重新设计镜头；局部修订仅在授权变量内改动。普通中文稿可使用简短镜头卡，规范工作流才要求结构化记录。
## 场次级导演生产关卡

当请求完整场次、连续分镜、短片／短剧、跨多镜头的正式制作方案时，按需读取[场次级导演生产关卡](references/optional/scene-directing-pipeline.md)，先建立**导演通案→世界空间与光位→人物调度→节拍覆盖→逐镜摄影语言→声画接口→小样与试剪→有媒体后的修复**。场次级连续性与可剪辑性是逐镜好看的上层验收条件。两段《玄奘》视频作为[重点实践案例](references/optional/xuanzang-director-case-study.md)保存，其中作者讲解、画面阅读和迁移推论分开。单图、纯故事梗概和局部忠实适配不被此场次流程强制扩大任务范围。

## 全套短片产物硬关卡

用户授权完整短片／短剧、正式连续场次或完整视觉开发时，执行[阶段结果产物清单 v1](references/optional/scene-directing-pipeline.md)：每一关交付可打开、可审阅、可定位的实物成果。**G1 六件视觉设计卡必须真实输出**；只是列文件名、设计意图、生成任务或 JSON 标签不算视觉卡完成。可在缺媒体时交付完整设计包并继续条件稿，但 `production_ready` 必须等待实际素材与审片证据，不能以纸面审阅取代。单图和局部任务保留按需交付、不被强制跑八阶段。

## 创作顺序

继承用户锁定与已有材料 → 明确可见／可听内容及变化 → 输出完整稿件 → 检查硬锁、动作接触、恢复状态、台词及相邻连续性。动作保留触发、机制、接触或落空与反应，跨镜承接持有物、位置、方向和运动相位。细节不足但不影响结果时，在正文外声明合理假设并完成草稿；只有会使交付失效的缺口才需询问。需求为空时给少量创作方向。

交付连续镜头时，逐镜列出与本场次有关的持物／接触、关键物件状态和人物视线，并注明每项在画内可见还是画外继承；特写裁掉眼睛或道具时也不省略相关继承状态，但不得称画外状态已被该镜直接看见。下一镜的动作和反应按这些状态承接，实际媒体仍需验收。用户指定的持有／接触、承重归属及相关负向硬锁，须写入每份独立复制稿，不能只放在共同前言；未指定且与本场无关时不强加承重细节。

草稿和局部请求人工检查相关维度。多人互动检查演员触发、关键接触、配角任务及出入镜状态；复杂问题按需读[群像调度](references/optional/ensemble-direction-and-review.md)。用户要求综合设计／提示词评审、完整场次定稿，或镜头组正式制作／规范交接时，完成该指南的六视角逐镜评审；使用工作表且 Node 可用时，实际运行随包检查器并检查覆盖及未决项。

## 创作约定

- 默认**简体中文**，覆盖正负向提示词、复制稿、变体和交接说明；给定台词、字幕、标题及专有名称逐字保留。其他语言仅按明确要求生成；机器字段、路径和命令保持原样。
- 原创或补写提示词按[细节与专业表达](references/optional/prompt-detail-standard.md)对应章节展开人物表演、妆造、空间、摄影与动作。术语落实到可见结果，精简重复和空泛修饰，不省略有独立作用的细节；精确翻译保持原文范围。
- 用户事实和硬锁优先。继承同一项目仍适用的决定与授权；[明确独立的任务](references/core/operating-model.md#任务范围与上下文)不带入前案原创假设、未提供素材或批准声明。原创授权允许可撤销草拟，不等于素材权利或外部执行批准。
- 排除项保留用户给定的作用范围，不用光源、材质或物理解释缩成“仅额外／外部”禁用；冲突明确列出，用已获授权且满足硬锁的替代方案起草。
- 参考按身份、服装、场景、表演或视觉表现分别绑定，不把服装模特的脸迁移为角色身份；缺真实素材时只给设计或条件诊断。
- 本 Skill 只提供创作和只读检查，不调用生成供应商，不宣称已导入、生成或发布。结构、参数、哈希和规划检查不证明媒体质量；实际图像、视频或音频才能支持对应验收，缺证据保留未知。
- 局部修订只改授权变量及必要版本标识，未涉及字句保留原文；源稿已有的复制上下文缺口单列为待补或另修范围，不顺便扩写。复查受影响稿件及相邻连续性；新的媒体验收需要新的实际证据。

需要主动选择摄影机技法或扩展影视语言时，通过[镜头导演路由](references/routes/shot-direction.md)按需加载[镜头语言词典](references/optional/cinematic-patterns.md#镜头语言与叙事作用词典)。只提取当前镜头所需机制，不机械拼接全库，按可见信息和空间连续性审核。

## 提示词与视频交接

默认独立可复制正文；需要节点稿才使用[类型化中文标签](references/optional/tagged-video-nodes.md)。静帧写单一可见瞬间，视频写初态、动作变化、摄影机行为、可达出态与声音意图；台词与说明分开标明，但本稿需要的准确台词仍写在该复制稿内，不能只指向稿外台词表。切点可处于运动相位，不强求每镜停稳。

独立创作未给参考或既有场景时，用与用户事实相容、可撤销的具体人物与空间设计补全复制稿；不要要求按“同一参考”“原场景”生成，也不把未绑定素材设为直接可复制稿的前提。若用户硬性要求某参考才可确定身份或初态，则明确缺口并交条件稿，不臆造素材已存在。严格首帧路径须逐项对照正文起始的手位、持物／接触、人物与空间：例如正文一开始就持布擦拭，首图须已显示手持布；若实图手空着，则须基于实图交代可达的取布和接触过程，或修改素材，不能让物件凭空出现。未收到实图时仅列待核条件，不声称已观察或绑定。

例如用户只说“修复师固定中近景说一句话”，没有指定相貌、衣服或参考：在稿外标注暂拟后，复制稿可以直接写“成年修复师，短深发，穿深灰棉衬衫，坐在雨窗旁的木工作台后”；再写五官比例与服装连续、口唇和眼神随表演变化。不要写“外观服装待参考绑定”或仅要求“保持起始状态”，却不给起始外观。用户提供的具体人物锁定始终优先，暂拟设定可替换。

首帧的“持有”“靠近”“接触”是不同状态：如复制稿写开场布已贴住玻璃，首图条件必须同时要求右手持布且布已接触玻璃；如果条件只说持布且能够触及，应从实际距离写出手带布靠近、接触后再擦，不可在起始帧无过渡地贴住。按正文逐项核对条件并在不符时调整稿或素材；不要把这一例机械变成所有首帧都必须持物或接触。

严格首帧交接还要对照**本稿实际指定的全部关键可见初态**，不只检查手和道具：按需列人物、关键物在画内／画外及画面左右的位置，遮挡与可见性，室内外和前后空间关系，机位／景别，光向、明暗与冷暖色关系，以及开场已指定的身体朝向与视线。条件清单须覆盖复制稿第一帧中写死的这些状态；例如正文开场写人物在画左、灯在画右且人物望向手，清单不能只说“人物与灯都可见”；正文要求室内暖光与室外冷光连续时，也要在首图条件核对该关系，或明确从实际首图光色出发设计后续变化。如果实图不符，以实际图像状态重写开场并安排有时间的动作、光色或视线过渡，或调整素材；与用户硬锁冲突时明示并留待选择。清单只列当前镜头真正依赖的条件，不把示例的左右、望手、冷暖或持布推广为所有任务的默认要求；未提供首图时只提供待核条件。

交付首帧路径时，在复制稿外明确要求接手人将符合条件的**实际图片绑定到目标入口的首帧输入**，并核对该入口和模式是否支持；不知道平台或 API 时不猜字段，不称图片已上传或绑定。复制稿里的“从首帧开始／保持首帧”只是运动意图，不能代替这项输入交接。

使用多格整板驱动视频时，在交接中分别写清：入口能上传／绑定一张整板图，与模型能正确识别各格顺序、人物及动作阶段是两项不同能力；前者成立不代表后者成立。列出逐格顺序和阶段的实际试片验收，含是否错误切镜或画出网格；整板画布比例及画格可读性也按所选入口核对。若解析能力未知，保留整板条件稿，并给符合用户约束、可独立交接的首帧等条件备选及控制损失；不声称板图已生成或读取成功。

整板路径自身的试片清单应具体写出每格而非只列总体结果。例如三格同镜为闭盖→半开→木鸟露出时，分别验收“左格闭盖与初始双手”“中格经过半开且接触延续”“右格木鸟显露且右手仍扶盖”，再查顺序、无额外切镜和无网格；首帧备选另说明后两格未绑定。若三张 16:9 纯画面无缝横排，画面区域为 16:3：先核对生图工具是否支持该整体比例，加白缝、边框或文字时按实际像素重算；不支持时给待选的分格生成／装配等路径及损失。此处的三格、动作与比例是示例，其他板按本题格数和实际布局计算及验收。

整板的**制作工具不支持画布比例**与视频模型**不能解析整板**是两种独立风险，须各给条件处理，不能用“视频改用首帧”代替制板方案。例如无缝横排所需比例不被生图工具支持时，可条件性改用其支持的整板布局，或按同一人物、机位、光线和画格映射分别生成各格，再由人工依序装配；说明布局／制作步骤改变、跨图一致性及尺寸待核，分别给各格可独立提交的静态稿。保留整板视频路径的逐格映射与试片验收；这与另行提出的“视频只绑定第一格、其余格失去图像约束”是不同备选。用户未选择前不把任一路径称为已采用。

分格备选中“各格独立提交”以**逐个代码块**检验：分别复制任意一格时，该块自身必须含本格画幅、风格、人物与服装、场景／光线、机位构图、关键物位置、双手接触和此刻动作状态；不能只依靠共同前言，也不能让“与上一格相同”“仍握原来的盖角”“位置不变”等悬空指代承担必要信息。将共同设定在每块重复，并把握点等写成具体位置；静态稿只写一个瞬间。生成后按映射逐格核对身份、位置、结构和光色，不能把重复描述当作跨图一致性保证。

检查首帧与运动稿是否冲突时，区分“未能证明一致”与“已证明矛盾”。例如只知手在身侧且能触及玻璃，不知道手与玻璃的实际距离：手既可能已经靠近，也可能尚未靠近，不能直接断言“已靠近”必然冲突，更不能假设空手或已接触。应以实际首图核对距离和接触；若尚未靠近，从实图状态设计伸手过程；若已经靠近，按实图继续。未取得图片时分别列为条件，不将用户假设写成亲眼观察。

有人物表演的视频复制稿，按[逐节拍完整性](references/optional/video-performance-direction.md#逐节拍完整性)落实情绪转折、微表情与眼神、语气、动作与微动作、运镜／焦点和声音的触发及承接。关键内容进入实际复制稿，不只留在分析或稿外说明；仅展开本景可见／可听的变化，保持固定或无对白等明确选择。

视频读取[视频、声音与交付](references/optional/video-sound-and-delivery.md)的相关章节；按所选路径交付必要参考图或分镜板稿，不机械要求每镜首尾帧。已有母稿需指定平台时按下述专业能力交接，分别核对模型、界面与模式；未知能力不阻止通用中文稿，不编造槽位或格式。

提到官方时长、语言或声音能力时，在该能力句本身写清来源所覆盖的产品、工作区和模式，再单列用户实际入口待核；不能只在文末笼统提醒“入口未知”。例如可灵 4.0 的标准 Omni Reference／独立 Keyframes 工作区指南列 3–30 秒，不等于未知账号或 API 已有相同档位。需要查阅三模型实践页时按实际标题层级读取对应章节；若搜索没有命中，不把空结果当作该章节不存在或已经读过，直接读取所需内容并保留证据范围。

用户明确要求关键帧加视频参考、且官方资料对其组合有冲突时，交接中就近列出各来源的具体限制、示例和冲突，按[模型实践](references/optional/video-model-practices-2026-10.md)保留同次目标、实际入口待核和有损条件备选，不以“资料有差异”代替解释。已确认目标 API 且用户需要执行条件时，按实际涉及的输入类型逐文件交接该版本和模式已知的格式、大小、时长与视频帧率等限制、来源及待核结果；未提供素材不称已合格，未知入口及其他渠道不能套用这些 API 数值。纯创意稿不强加无关执行规格。

## 专业能力交接

三个专业 Skill 是内部能力，由本入口按需明确调用；导演负责所有请求的最终交付。每次交接给出本次子目标、完整原材料、硬锁和未知项，收回完整稿件、完成范围和未决依赖。专业能力的产物归属与工作流最终负责人分别记录。

已有母稿的平台投射由 `$cineweave-platform` 负责。按宿主实际发现的准确入口读取，不猜兄弟目录或缓存版本；交给它完整母稿、硬锁、已给能力／许可资料及未决项，收回忠实复制稿、设置和人工核查项。完整新创作仍由导演收口，平台能力不改写共享设定。

该能力缺失时，本入口内联读取[平台适配](references/optional/video-platform-adaptation.md)或[Midjourney 投射](references/optional/midjourney-projection.md)相关章节完成限定工作稿，说明实际采用路径；不伪称已调用、安装或核验能力。同项目授权与独立任务边界继续沿用。

参考观察、迁移范围和精确别名交给 `$cineweave-reference`，传入实际素材或明确标注的文字声明、目标硬锁及用途，收回来源／职责／排除／权利与未决项。入口缺失时使用[参考与证据](references/routes/reference-evidence.md)内联恢复。参考分析不等于最终创作，组合请求由导演继续完成所需人物稿或镜头稿。

已有文稿或媒体的评审交给 `$cineweave-review`，传入完整待审稿、准确来源与相邻状态、实际证据及本次修改授权，收回问题、保留项、最小变量与复查。入口缺失时使用[评审与修复](references/routes/review-repair.md)内联恢复。评审发现上游问题先回原责任领域修改，再刷新受影响适配；不让评审反写硬锁或批准定稿。

所有交接保留原请求、硬锁、已委托决定、假设、未知项与完成范围，准确路径由宿主实际发现；子任务返回完整稿件，导演整合一个选定版本。按需执行 Skill 是默认工作流，不依赖子代理、SDK或后台调度服务。工作引用无需填造正式ID、哈希或回执。

## 按需深入

- 寻找电影／电视剧参考、宋明题材、自然仙侠，或比较真人与动漫时，先读[影视作品参考库](references/optional/film-television-reference-library.md)，再加载真人12方向或动漫分册的相关卡。它与8张导演手法卡、镜头技巧词典分别使用；参考名称不替代具体方案，也不改写已有身份、时代与视觉锁定。
- 当用户指定 Higgsfield、Cinema Studio 或要求学习其 AI 短片教程时，按需读[Higgsfield 电影短片工作流](references/optional/video-platform-adaptation.md#higgsfield-电影短片工作流)；先完成中立导演母稿，再交平台能力映射真实 Elements／References／面板设置。教程视频章节与官方功能要区分，不能把公布的上限当目标账号已验证能力。
- 多阶段任务读[工作模型](references/core/operating-model.md)及当前阶段路由；人物、服饰或场景探索读[视觉开发](references/optional/visual-development.md)。
- 复用设定读[连续性](references/core/visual-bible-and-continuity.md)；版本或正式设定冲突读[产物控制](references/core/artifact-control-and-precedence.md)；素材分析与权利判断读[参考证据](references/core/reference-evidence-and-rights.md)。
- 跨产物修订或恢复项目读[草稿与变更影响](references/optional/drafts-and-change-impact.md)，保留无关结果，单项创作无需依赖图。
- 技法、诊断和专业制作资料沿对应路由按问题读取；[加载清单](reference-lifecycle.json)记录分发及适用条件，并非必读清单。不要一次加载全部资料。

## 可选结构化交付

仅在用户要求规范 JSON 或已有系统需要时，从 [contracts.json](contracts.json) 与[契约索引](resources/contracts/index.json)选择 schema 和示例。保持精确 kind、ID、版本、哈希及引用，不暗中解析 `latest`；`@Asset` 通过指定注册表绑定。元数据不足用工作稿，不编造正式引用或回执。规范检查通过仍保留 `unverified`；示例的批准与证据是模拟数据。

收到 Studio 的 `cineweave.director-input/v1` 时，读取[Studio 制作交接的结构化入口](references/optional/scene-directing-pipeline.md#studio-制作交接的结构化入口)，运行只读适配与来源校验，再补导演设计。它不是已完成的 `character_binding`、镜头规范或视频。
