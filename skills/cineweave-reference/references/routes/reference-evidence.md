# 路由：参考证据（reference_evidence）

用于用户提供图像／视频、要求参考分析、需要有范围的迁移规则，或使用 `@Asset` 别名的情况。始终加载[参考证据与权利](../core/reference-evidence-and-rights.md)。

## 流程

1. 确认媒体真实可访问，并说明用途。
2. 创建或接受精确的 `ReferenceAsset` 身份，不暴露私有定位地址。
3. 只将可见证据拆为原子观察。
4. 每项声明标记 `visible`、`declared`、`inferred` 或 `unknown`，并注明置信度。
5. 识别污染：源身份、服装、标志、文字、地点、构图、风格、裁切、修图或不确定元数据。
6. 评审是否适合目标及其权利范围。
7. 精确目标产物存在后，才创建 `ReferenceBindingSet`。

人物参考需分开：脸部身份、身体身份、形态、当前皮肤／材质状态、妆容、头发、服装、表情、姿势、拍摄、灯光、构图和表现方式。稳定身份进入人物领域，当前造型进入外观状态，表现方式进入风格，视点进入导演。

源到目标迁移要记录保留、替换、排除、允许变换、待决事项和验收证据。“用这张图”不等于迁移策略。

多参考合并前，先建立简短的来源／角色／迁移／排除表。用户指定身份、服装、风格角色，只授权对应迁移：默认排除服装图模特的脸和身体，也排除风格图的服装，除非另有要求。同图承担多个角色时拆成独立范围的观察。冲突按用户指定角色及已有目标锁定解决；只提出这些权威仍无法解决的重大歧义。

只有文字描述时，将其标为声明并提供暂定迁移计划，不能声称看过图片。最终提示词应检查是否漏入排除特征；计划本身不能证明生成身份一致。

参考精度由需要约束的决定确定：探索氛围可保持宽松，关键交接则明确姿态、持有和空间锚点。不能因参考含有某细节就锁定无关内容。只需布局时，可在授权范围内提出干净布局代理图，以排除无关身份和纹理；计划中的代理图不是已有资产。

连续候选出现劣化时，先与原始参考比较，再判断是否由迭代导致。保留来源链，指出实际变化，建议返回最干净且相关的权威来源，不把有缺陷的派生结果提升为正式设定。本节对 [Leos 参考控制讨论](https://github.com/MasterLeos/leos-six-department-directing-team-skill-v1/blob/2ed50edb3c7838fc9ffb68e50824e0ebff59c7d4/references/spatial-and-assets.md)作条件性改写，不保证更强控制或转换参考必然改善模型输出。

## 别名规则

别名通过已提供的精确 `AssetAliasRegistry` 解析，包含范围、版本及内容哈希。不能推断全局别名、归一化成另一个资产或选择最新候选。

## 平台适配绑定

平台适配只能通过精确 `ReferenceObservation` 引用使用参考，包含一个有类型的角色、保留清单、排除清单和由人工确定的外部定位占位。账号个性化、情绪板和平台风格码属于适配状态，不是视觉证据。提交过定位地址或代码，并不证明输出保留了预期角色。

## 质量关卡

每条观察一个主角色；源和选择器精确；可见事实与推断分离；迁移与排除项不重叠；阻止身份／地理污染；权利按用途判断；不可访问媒体不能描述为已经观察。

可选规范输出（仅在请求结构化交接时）：`ReferenceAsset`、`ReferenceObservation`、`ReferenceBindingSet`、`AssetAliasRegistry`。
