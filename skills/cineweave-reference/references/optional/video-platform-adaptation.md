# 可选参考：以证据范围为边界的视频平台适配

平台来源研究日期：2026-09-13；多路径创作设计更新：2026-09-15，后者不代表平台资料重新核验。涉及视频路径选择、多镜头提示词、分镜板／多模态参考、指定平台或时间交接时加载。本文件是规划指南，不是执行适配器、支持模型注册表、导入 schema 或可执行 Skill。模型／界面变化及提交前重新核验。本 Skill 不安装工具、不取凭据、不上传、不消费点数、不执行生成。

## 使用正确的权威来源

分别绑定五项：平台、精确模型／版本、界面（画布／手工面板／Agent／CLI／API）、生成模式、当前控制证据。模型厂家描述功能不证明平台开放该功能；项目导出长度不是单次生成上限；最大时长不是全部可选档位；`@` 名称不是已上传资产或参考槽位。

证据工作表包含来源地址、发布／更新日期、访问日期、实际读取的是全文／搜索索引摘要／界面、声明范围、不确定性、目标账号／模型／界面及下次核查。无支持能力不能写成已具备。检查器中的证据声明不等于外部核验。

2026-10-10 对 OpenAI 图像、Sora 停用、Runway Gen-4、Google 视频最佳实践及 Midjourney 参考职责的专项复核见[AIGC 控制与评审](aigc-control-and-evaluation.md)。其中停用模型不进入可执行候选，负向和对白包裹语法按精确模式处理。该复核没有刷新下表 LibTV／小云雀／Flova／Seedance 的历史资料，不把旧记录的访问日期改成今天。

视频工作表的 `checkedAt` 填有效公历日期 `YYYY-MM-DD`。不存在的日期不能完成能力声明，也不能用于时长或参考数量政策；正确日期只说明格式与历法有效，来源真实性、时效和账号适用性仍需另行核验。

### 能力证据的层次与评估日期

| 证据层次 | 可以支持的声明 | 不能据此推导 |
| --- | --- | --- |
| 静态目录 | 来源当时列出的模型、模式或参数名称 | 目标账号当前可用、控件实际生效或生成成功 |
| 官方文档 | 所述版本、界面及模式的公开功能约定 | 另一个平台、账号、模式或版本开放同样控制 |
| 目标账号／界面控件 | 查阅时该账号在指定界面可见的选项及限制 | 提交已成功、返回采用了该值或本镜头质量通过 |
| 实际返回 | 已提供来源对应的解析设置、返回元数据及可访问媒体 | 所有后续候选可靠、未观察维度通过或其它模式支持 |

每项声明保留平台、模型技术 ID（technical ID）、准确 `modelVersion`、`surface`、`mode`、查阅日期、来源和适用范围；未知版本明确未核验，不用展示名、workflow ID 或账号句柄替代模型技术 ID。这些是人工证据工作表内容，不新增能力注册表或根契约字段。同模型不同模式、官方文档与账号控件范围不一致时分别记录，不能以静态目录提升为当前实测支持。

只读检查器的 API 为 `validateVideoWorkbook(book, { evaluationDate } = {})`，CLI 可传 `--evaluation-date YYYY-MM-DD`。提供日期时，先检查有效公历日期，再检查能力、`durationPolicy` 和 `referenceLimits` 的 `checkedAt` 不晚于它。省略日期保留原一参数调用，报告日期比较未核验的警告；不读取系统今天，也不自动使旧记录过期。重新核查由本任务所需控制、版本／界面变化及来源冲突决定，日期或算术检查不会把 `capabilityVerified` 提升为真实支持。

能力未知只阻止依赖该控制的最终适配确认。仍完成平台中立的中文创作母稿，将未决控制留在交接清单；不能为了较简单的参数改换用户指定模型、无声裁改准确文案，或删掉必要身份、画幅和时间要求。

## 先定参考职责，再写提示词

对每份实际来源记录准确资产 ID／版本或可访问文件、媒体类型、指定职责、允许迁移、排除特征、裁切／时间范围、目标人物／物体、权利状态，以及上传后的真实平台槽位。未决绑定保持未决，同一别名在节点、适配和结果记录中一致。

可能职责包括身份、当前服装／外观、场景几何、道具、风格、首帧、尾帧、表演、运镜、声线、音频时序、特效、来源片段。一份素材可分别承担多个有界角色。声线／时序可来自音频，也可在界面支持时来自明确标识的视频音轨；不强制无必要提取，也不假设视频有可用声音。不误迁移表演者的脸、服装图的身材、运镜参考的主体或风格来源的地理。

先区分板的职责：三视图负责形体／外观，表情板负责表演研究，分镜板负责镜头构图与顺序，情绪板负责视觉风格。按任务选择整板或派生素材，不把所有拼图一律拆开，也不将同一人物的不同画格当成新人。整板读取方式与执行可靠性需核验，槽位增多不是必须填满。

冲突依据用户分配角色及已批准锁定解决，不平均混合不兼容脸／服装，不让文件顺序无声决定。遮罩／裁切只能在授权迁移范围内，派生图具有独立版本身份。

## 模式选择与明确替代

以下创作路径并列可选，没有统一的“先首帧再视频”前提。先选**输入条件**（文字、单首帧、首尾图、多媒体、分镜板），再选**镜头组织**（单镜或有切点的多镜）。全能参考可以指导单镜也可以指导多镜；分镜板既可作为全能参考的一项，也可按需裁切成单图输入。用户已经指定路径时优先完成该路径方案，不能无声替换成首尾帧流程。

| 模式 | 适合何时 | 交接内容 | 不支持时的明确替代 |
| --- | --- | --- | --- |
| 文生视频 | 没有首帧素材、需要直接设计运动场景 | 完整可见初态、动作、运镜、光色、时长和声音意图；先核验文字驱动模式 | 先制作首帧再走图生视频，注明新增素材依赖 |
| 图生视频 | 已批准图像定义镜头可见状态 | 真实首帧、时间变化、独立人物／摄影机／环境轨、稳定终态 | 保留草稿并要求支持模式；文字提及不等于附件绑定 |
| 首尾帧 | 两端构图都重要 | 兼容首尾素材、连续路径、允许变化、真实终点语义、尾余量 | 设计两个相关镜头或参考驱动运动，说明失去原生尾帧约束 |
| 多模态／全能参考 | 身份、运动、场景、声音来自不同素材 | 角色到槽位映射、动作、时间窗和排除 | 缩减为支持模态，不无声丢身份、声线或故事要求 |
| 提示词驱动多镜头 | 由文字编排镜头、切点和表演，可结合全能参考 | 共享设定、逐镜构图／动作／时长、镜间状态、声音与明确剪切 | 若目标界面不支持，交付拆分请求方案并说明变化，不默认放弃原多镜设计 |
| 分镜板参考视频 | 已有或先生成九宫格、条带、其他布局的分镜参考图 | 整板生成稿、画格到镜号映射、参考职责、顺序／时间与视频全文 | 整板支持不足时给必要裁切格或独立镜头方案，保留原画格内容与顺序 |
| 表演驱动 | 精细表情和身体时序关键 | 有适当同意的表演媒体、来源时序、目标身份、所需控制 | 文字指导或反应镜头覆盖，说明精度下降 |
| 延长 | 需继承连续边界 | 真实原片、准确边界、只含续段的动作、重叠和返回时长语义 | 明确切到新镜头，不反复延长已劣化来源 |
| 有界视频编辑 | 合格片段只需局部修正 | 来源版本、时间范围、所属变量、通过维度、验收比较 | 单变量重新规划／生成，不把文字请求说成已完成非破坏编辑 |

剧情有动机时，首尾图可以同时改变姿态、视角和光。检查路径兼容与难度，不断言多个维度变化必然变形。厂家支持控制与本镜头实际成功是两件事。

## 导演方案到复制稿

导演方案说明观众如何理解事件；复制稿只保留所选路径能够承载的画面、动作和声音。不是将整份方法说明原样贴到模型入口。以下为平台中立的交接方法，沿用上述已注明日期的能力证据，不代表在 2026-10-11 重新核验全部平台。

| 路径 | 初态与不变量由谁承担 | 复制稿重点 | 需另行核验的控制 |
| --- | --- | --- | --- |
| T2V | 文字完整定义主体、空间、当前状态、共同视觉与必要道具 | 触发、变化、相机／焦点、出点；声音意图按实际支持保留 | 时长、画幅、多镜、原生声音和参考支持 |
| I2V | 实际源图定义可见身份、服装、空间与起始姿态 | 描述从真实初态发生的变化；用位置辨认人物，保留关键动作与时序 | 附件确已绑定、场内运动、相机控制；源图能否开始动作 |
| 表演参考 | 身份／造型与录制表演分别指定职责 | 已选演法的刺激、眼线、任务和过程；排除录制者造型、背景与采集光 | 身体／手势／面部通道、声音来源、长度及目标人物映射 |
| 剪辑与声音 | 已返回媒体、准确台词与实际采用区间 | 切点、信息揭示、声音先入／后出、连续性与必要声层 | 是否已有合格覆盖和音轨；不能用剪辑计划补造素材 |

### 同一决定的文字与图像路径

原创演示简报：固定机位的八秒门厅单镜，甲想让乙多留片刻，但只说“你拿走吧”；甲将雨伞递向乙，乙触到伞柄却未拿走。人物、门的位置、中性日光和无雨天气不变，动作没有附加回忆或新的来人。下列八秒是导演设计，不是任何模型的可选档位；当前没有真实源图或视频。

**T2V 通用稿：**

```text
八秒单镜，16:9横向写实。白天的安静门厅，关闭的门位于画面右后方，门边地面干燥。一名穿深灰棉衬衫的成年女子站在画面左侧，右手握住收拢黑伞的弯柄，伞尖触地；一名穿浅灰外套的成年男子站在她右侧，两人相隔一个自然递物距离。他的左手空着，停在身前，身体略朝向右后方的门。固定眼平双人全景保留两人从头到脚、完整伞柄和伞尖，手部交互在画面中足以辨认；左侧日光有柔和方向，脸与深色衣料仍可读，光色和焦点保持一致。
女子看向男子，右手把伞柄向他缓慢送出一小段，伞尖沿地面轻滑，不悬空。她对他说：“你拿走吧”，唇与下颌随准确发音自然运动。说完，她仍握着柄，等待对方；男子先看伞柄，再伸出左手，用指尖触到柄的另一侧。他没有接过重量或拉走伞。女子察觉他没有拿走，手部动作停在当前递出位置，目光仍在他脸上。男子指尖留在伞柄上，两人的停顿持续到出点，伞仍由女子持有、伞尖仍触地。摄影机全段固定，接触不被衣袖遮住，不增加笑、泪、雨、回忆或额外人物。连续室内底声、伞尖轻擦地面的声音与准确对白为声音意图，男子没有额外台词。
```

**I2V 待绑定运动稿：**只有实际首图呈现左女右男、女子右手持伞且伞尖触地、男子左手空闲，以及允许递物的距离时，才可沿用下面的起点；未取得图片时不宣称已检查。

```text
左侧女子看向右侧男子，保持右手握住黑伞弯柄，把伞柄缓慢送向对方，伞尖沿地面轻滑。她对男子说：“你拿走吧”，说完仍握着伞等待。男子先看伞柄，再伸出空闲左手，指尖触到柄的另一侧；他不接过重量，也不拉走伞。女子的手停在递出位置，继续看向他的脸；男子指尖保持接触，伞仍由女子持有，伞尖仍触地，停顿持续到采用出点。摄影机固定，焦点保护脸和接触点。室内底声、轻微擦地声与准确对白为声音意图，男子无额外台词。
```

图像若呈现不同持手、伞已在乙手中、伞尖出框或两人不可达，先修该依赖，不用运动稿强行重置源图。独立提交参数设置八秒是否可用、是否需要生成余量以及准确台词的原生声轨仍待目标模式核验。用户只要一条稿时只交付对应正文，不自动附带另一条或新增制作任务。

这项导演决定也可交给表演参考或剪辑，但职责不同：录制者演“递出后等待对手是否接取”，不是重演某位导演的招牌表情；角色素材维持身份和场景，表演片只负责选定动作及节奏。已有素材剪辑时，保留“触柄但未承重”的实际区间；没有合格接触画面则是待制依赖，不能用遮挡或反应插镜冒称已展示交接。

图像／视频母稿对照检查线索、硬锁和出点是否仍在复制稿中。适配可以改包裹语法、删已由实际源图承担的重复外观，却不能删未被其他输入承担的认知线索、接触步骤或准确台词。声音无支持时保留独立声音交接，并说明生成视频没有该原生控制，不把计划写成已录制音轨。

## 提示词驱动多镜头与全能参考

先列共享身份、外观、空间、光色及声音基线，再按镜号写时间范围、景别构图、机位运动、人物动作表情、出入点及剪切方式。时间码是导演设计，不是天然具有逐帧约束力的参数。没有图片也能完成文字多镜方案；使用全能参考时按职责继承素材，由提示词规定各镜的初态和变化，不必伪造首／尾槽位。

同一参考在何镜生效应明确。例如人物图负责 S01 至 S03 的身份与妆造，场景图负责全段空间，动作视频只提供 S02 的转身节奏，声音参考只提供指定说话人的声线。共用人物不代表每镜复制参考图的姿势；不同镜头可以继承同一场景而改变构图。参考分镜板不自动覆盖更明确的人物身份图。

多镜稿写明切镜，而非让相机在不可能的路径中串联全部构图；相邻镜头可以有动作匹配、反应切或有理由的时间省略。每镜完整覆盖人物、空间、摄影、表演和声音的相关细节；共享信息在本段可复用，独立提交稿需展开必要内容。实际生成后检查漏镜、并镜、重排、时长偏移、换脸与声音错位，不能从文字时间线推断模型已执行。

## 分镜参考板驱动视频

分镜板是时序／构图参考，不是视频的分屏画面。先确定板用途：各格是不同镜头，还是一个镜头的起势、接触与结果；两者不可混用。九宫格不一定代表九次切镜，也不要求所有故事必须九镜。排版可以采用 3×3、2×2、横向条带、纵向条带或不等幅布局，画格数量由叙事决定。

1. **先写映射。** 明确阅读顺序、格位与镜号／动作阶段、每格的时间或区间及共同资产。规则网格可用行列位置定位；不等幅板明确格位边界和顺序。不得仅写“按图动起来”。
2. **生成板图。** 交付完整整板提示词，逐格描述一个瞬间的构图、人物状态、接触和空间，保持身份、发饰、衣层、道具及光色连续。整板画布比例和各格画幅分别记录；例如三张 16:9 画格横排的纯画面区域为 16:3，排版工具边框另计。目标生图工具不支持该长宽比时采用支持的画布布局或分格后装配，并说明变更。编号可放在画外标注层，顺序映射不依赖模型正确生成文字。
3. **选择引用方式。** 整板可作为多镜顺序与构图参考；需要清晰局部或界面仅接受单图时，按映射裁切必要格。裁切去掉网格线与编号，保持画格内容和身份，记录来源格位。整板不能未经说明塞入首帧槽位，否则可能把九宫格本身当作待运动场景。
4. **写视频全文。** 指明按画格顺序依次呈现全画幅镜头，画格之间发生指定切镜或同镜动作延续，补足格间动作、时间、运镜和声场。成片不显示分格边框、编号、多余重复人物或逐格扫描动画；若用户要分屏，则按明确布局设计而不是删除分屏。
5. **审阅真实结果。** 分别检查板图的身份／空间／顺序，以及视频的逐镜覆盖／动作插值／衔接。板图合格不证明视频成功；无真实素材时仅交付待生成方案。整板支持、最大图片数量和时长档位按具体模型与界面核验，不把本指南当作能力声明。

### 三格参考板与多镜视频示例

以下为原创无对白段落的设计草稿，不是已上传图片或厂商参数；可用整板参考，不要求先做首尾帧。三格均为独立镜头，从左向右对应 S01、S02、S03；拟成片各三秒，共九秒，源余量按实际剪辑需要另定。身份基线是一位约三十五岁的成年男子，方圆脸、短黑发，无胡须与装饰性彩妆，浅棕自然肌肤；灰绿棉衬衫外穿深蓝斜纹围裙。场景为木工房，北墙工具架、西窗柔光、中央木桌，摄影机保持桌南侧。

**整板图像稿：**

```text
绘制横向三格分镜参考板，每格为16:9横向画幅，从左到右阅读，画格间用窄白色间隔分开，格内不写文字。三格是同一位约三十五岁成年木匠和同一间木工房：方圆脸、短黑发、无胡须，浅棕自然肌肤，灰绿棉衬衫和深蓝斜纹围裙保持一致；北墙深木工具架、西侧窗光、中央磨损木桌。整体低饱和木褐与灰蓝，柔和西窗光塑造人物和桌上物体。
左格S01：桌南平视中景，男子站在桌北侧，双手扶一只放在桌中央的浅木色长方盒，两手分别贴盒身两侧；盒盖闭合，背侧铰链位于远离镜头的一边。他期待而克制，眉间放松、双唇轻合，目光落在盒盖，肩部微向前靠。
中格S02：桌南偏西略俯的手部特写，男子右手握住盒盖前沿，左手压稳盒身左侧，盒盖刚抬起少许，铰链和手指接触可辨；同一灰绿袖口与木纹保持一致。盒内尚未完全显露，桌面阴影方向与左格相同。
右格S03：桌南偏东平视胸上近景，男子看向画面下方已打开的木盒；安心且满足的轻度笑意表现为面颊略提、下眼睑轻收、闭唇浅笑，下颌放松。近处眼睛清晰，前景下缘露出半虚化的竖起盒盖，不遮住面部。三格采用一致的摄影写实质感，不复制出额外人物或第二只木盒。
```

**整板参考的视频稿：**

```text
使用已选三格分镜板作为同一人物、工房、木盒与镜头顺序的参考。左、中、右格分别指导S01、S02、S03；每格依次展开为全画幅16:9影像，不拍摄或扫描一张分镜纸，不显示边框、格间白缝或编号。共九秒，三镜硬切；各镜摄影机固定在桌南侧相应位置。
0至3秒S01：从左格的中景开始。男子看着闭合木盒，略向前靠，左手扶稳盒身，右手从盒侧移到盒盖前沿并轻握；至切点盒盖仍闭合，脸上保持期待而克制的闭唇神情。
3至6秒S02：动作匹配切到中格机位。承接右手已握前沿的状态，左手压稳盒身；右手沿背侧铰链向上掀盖，经过参考格的微开状态，继续至盒盖接近竖直，露出盒内一只雕刻完成的浅木色小鸟。盒身不移动，双手接触连续，右手仍扶住盒盖。
6至9秒S03：切到右格的胸上近景。男子视线仍落在盒内木鸟，看到成果后眉间舒展、肩部张力下降，面颊轻提、闭唇浅笑；不看镜头、不露齿、不改变脸型。盒盖留在前景下缘，右手在画外继续扶盖。
西窗光及桌面阴影持续一致。全段保留安静室内底声，S01出现轻微棉布摩擦，S02开盖时有细小木铰链摩擦，S03仅余环境底声。无对白、旁白或音乐；不新增撞击声，也不以人物换脸或盒子形变连接三镜。
```

板图中间格是 S02 过程中的构图关键点，不是强制 S02 开始即处于微开；视频稿补上从闭合到该状态的连续动作。需要更精确起点时可以另制关键格，但不能因此把整板路径强制重写为每镜首尾帧。此例的木鸟是原创视频设计补全，图稿中尚未露出；若需精确外观，再为它增加实际道具参考。

## 分平台交接

**LibTV：**交付标签节点表、依赖关系、参考职责表及模型／界面检查清单。画布节点名称与模型提示词分开。先确认当前 CLI／Agent 的真实 schema，再生成导入文件。公开下载链接不证明有画布导入器；没有 schema 和真实导入测试，不称“可直接导入项目”。

**小云雀：**交付项目简报、场景／人物资产、标签镜头稿、准确对白表和有界修改要求。参数／槽位映射等待实际模式。不能从智能视频或短剧宣传推导单镜时长，也不从同厂其他产品推导专业控制。

**Flova：**全作品要求放到最终视频规格（Final Video Spec），复用流程规则放 Skill／项目文档，节点当前任务放提示词草稿（Prompt Draft）或媒体设置。生成前明确审阅提示词、参考和设置。选择准确素材版本，不依赖未记录的收藏。局部评论写一个要改变量及保留维度，再比较实际返回设置和媒体。

## 适配不是盲目拼接

标签母稿是创作者编写源。平台适配交付四项：真实附件与已解析槽位；模型可读时间／视觉语言；有文档的时长、画幅、声音等原生控制；人工核查清单。节点 ID、预算、证据和剪辑窗口不进入语音合成或画面文字。上述来源没有建立 XML 风格标签通用识别协议。

原生摄影机控制、文字运镜、角色明确的路径参考中选一个主要权威；可补意图及连续性，不叠加冲突指令。负向词、时间戳精度、选声、表情强度和参考权重逐界面核验，不虚构共通滑杆。

### 外部人工交接与返回

在已有镜头／候选记录旁，分别保存请求值、外部界面解析值及实际返回值，关联准确创作来源、shot、take／候选版本和可访问媒体。只有已提供的元数据才能填写；媒体属性的声明与实际测量／观察分开，缺失设置不妨碍限定范围的媒体评审，也不补造任务 ID、seed、回执或执行状态。此清单服务人工交接，不是供应商请求／回执协议。

请求与解析／返回值不一致时，先核对输入绑定和实际设置。若调整影响硬画幅、身份、必要动作时序或准确台词，回到相应设计并说明取舍；不静默换比例、压时长、加速或截去台词。保留已通过片段及实际采用区间，只将失败部分交给[外部失败分诊](generation-diagnostics.md#外部失败分诊与恢复交接)，音频时长与同步回流沿用[声音与交付工作表](video-sound-and-delivery.md)。

### 复制稿的内部闭合

规范交接采用 `PromptProjectionPlan` 时，适配正文与其最终正文必须逐字符相同；不进行 Unicode 归一化，不替换准确台词、中文引号或标点。参数先按唯一 `order` 排列，`parameterId` 唯一，每个已定义方言的参数由 `name` 和 `value` 生成准确 `rendered`。参数尾以一个 ASCII 空格连接这些渲染值；无参数时 `copyText` 等于正文，有参数时等于正文、一个 ASCII 空格和参数尾。这是该契约的内部装配规则，不能据此宣称所有平台都使用文本参数尾。

已定义的 Midjourney 参数按该方言处理：`--raw` 等 flag 只有 `true` 对应无值开关；`false`／`null` 没有已定义表示时不能猜成字符串或省略。多个风格参考码或 URL 可由一个 `--sref` 字符串值承载，不能从多值能力推导重复 flag 支持。未知方言或未知参数只核对记录中的有序渲染值与复制稿闭合，其语法、同名参数重复和模型支持保留未核验。该静态检查不更新平台资料的原核验日期，也不证明当前账号能力。

每个参考 `bindingId` 与定位占位符唯一，`renderedPrompt.referencePlaceholders` 与声明绑定准确闭合，正文出现的 `REF_` 占位符也必须有声明。附件界面的占位符可以保留在旁路槽位表，不要求写进复制正文。相同 `surfaceSlot` 名称可能表示可容纳多个输入的参考类别，重复类别的数量和互斥关系等待精确能力／界面证据；不能把所有类别都推成单素材槽。账号句柄不得冒充 URL、路径或查询地址；返回码状态为 `returned_exact` 时必须提供准确码，待提交或不适用时不得填一个猜测的返回码。

`containsPrivateLocator: false` 是声明，仍需检查实际适配复制稿中的私有本地路径、凭据和签名定位链接。普通画面文字中的公开 URL 不因其是 URL 就被禁止。母稿与适配可以采用不同措辞；可追溯的合理改写通过准确源和角色／能力／许可上下文评审，不要求两份全文相等。

实验的 `baselineVariantId` 必须指向唯一基线，各 `variantId` 唯一；基线 `changedVariable` 为 `null`，单变量测试必须命名非空变化变量。基线与测试可持有不同复制稿。自由文本的固定项、预期效果和“只改一个变量”不能靠关键词自动证明，仍需对照实际提交设置、参考和返回媒体评审。

参见[类型化节点](tagged-video-nodes.md)、[表演与摄影机轨道](video-performance-direction.md)、[时长及余量](video-timing-and-handles.md)。保持非执行、证据、权利及精确正式设定边界。

### 二、把视频教学拆到 G0–G7

1. **G0 故事／场次**：一句话写人物的行动、观众获知顺序、场次结束的变化；按视觉节拍拆镜，不用每个模型时长定剧情。源于官方 2026-10-23 10 秒海边车站演示和《Santiago》案例。
2. **G1 视觉／资产**：先锁身份肖像；另列当前服装、场景平面、可交互道具。多演员分别建独立人物参考，保持身高关系／服装归属，避免一张双人板导致混脸。历史故事要分清史实证据、艺术设计与动态画面表现。
3. **G2 世界地理**：统一左／右、入口／窗位、光源位置与接触点，单独出地理与 Blocking 草图。镜内变机位不许让墙、门、灯和人物座位换边；参考视角不能冒充精确三维测量。
4. **G3 演员表演／动作**：给每个演员目标、刺激→回应、眼线、手势和持物；情绪词服务行动。两人对话或打斗要先锁交互位置和相位，难点不靠“极致真实”形容词解决。
5. **G4 镜头覆盖**：每镜只选能承担叙事任务的景别、机位、构图与一个主导运镜（必要时可设计连续多技法）；明确初位置、触发、路径、终构图／焦点、允许切出的运动相位。镜头无需总是推拉摇移。
6. **G5 节奏／剪辑／声音**：明示连续／重看／跳时、首尾帧匹配、画面轴线、声音源与 J-cut/L-cut；`Tempo` 只是目标平台的风格控制，不能替代 CineWeave 的逐镜整数帧时间线。
7. **G6 候选与试剪**：先挑身份＋复杂接触／反打／转场等高风险组做小样，再扩张。分别记录参考绑定、模型、界面、模式、设置声明、候选与实际采用区间。没有媒体时一律 `pending_media`。
8. **G7 审片与归因**：首帧／中帧／尾帧＋切点复核，分声画两遍；检查面部、人数／空间、持物、动作因果、机位／焦点、光色和声音。选择局部编辑、重生或重剪后，再用真实候选复验。

| 供应商面板／语法 | 来源 CineWeave 稿件 | 提交前核查 |
| --- | --- | --- |
| Project / Elements / References、`@` 引用 | `CharacterSpec` 的 Identity 与 AppearanceState、`SceneSpec/State`、道具和 ReferenceBindingSet | 参考确已上传？别名是项目内真实名称？每份参考的 Preserve/Replace/Exclude 清楚？是否有使用权？ |

| Emotion Wheel、对话和 Audio | `PerformanceTimeline`、准确台词和 `video-sound-and-delivery` | 预设只提供情绪方向，关键刺激与情绪转折仍在镜头正文；原音、配音和拟音职责分开 |

**编译交接**：先给一份中文供应商中立镜头母稿，后由 `$cineweave-platform` 输出 Higgsfield 的【项目与参考绑定表／面板选择表／逐镜或多镜复制正文／兼容与未知／人工操作顺序】。如果原生面板已独立指定镜头与光学参数，正文主要写可见行为、动作时序、物理与声音，避免在正文重写一个与面板冲突的机位。所有决定必须能从母稿逐项追溯，未知保留待核验。

#### 选择单次多镜还是拆镜

- **单次多镜可作为候选**：单地点、少角色、短连续行动、可容许模型决定次要切点的叙事；仍写清每段画面、相邻状态及音轨。
- **拆为独立镜头再剪**：双方近身接触、精确道具损毁／消失、复杂越轴、台词严格精确、转场必须压在指定帧或需要跨镜重用一件资产时。分组切片使失败只影响该镜。
- **续接或修补**：只有真实上段媒体且目标模式支持 `Sequel/Prequel` 或局部编辑时才列为可提交候选；锚点、转场和声音桥必须再验，不假设“Extend”自然跨越空间／时间逻辑。

### 五、失败分诊，先保留已通过的内容

| 可观察症状 | 最小责任领域与优先动作 | 复验 |
| --- | --- | --- |
| 两个人脸混合、衣服／道具互换 | `character`／`reference_evidence`：拆分人物身份和当前外观参考；明确人数、身高、空间两侧与排除；先对高风险镜重生 | 比对每个演员的正脸、侧脸、服装、持物 |
| 人物交换座位、门窗镜像、违背轴线 | G2／G3：回到空间地图、Blocking 和光位，重排生成输入，再由 G4 核机位 | 同一世界方向下比对反打、眼线、切点 |
| 动作接触不成立、摄影机路线错 | `action`／`shot_direction` 修起态、触发、接触和终态；精确失败时**重新生成／拆镜**优先 | 检查运动相位和物体重量感、冲量反应、持物连续 |
| 已有正确画面，只有局部对象／脸出现缺陷 | 模式支持时列局部编辑候选；不承诺其他区域天然不变 | 逐帧检查编辑区、边缘和“未变”区域 |
| 只是光向、色彩或画幅问题 | 依实际工具试 `Relight`／`Edit Color Palette`／`Reframe`，但光向与剧情相冲突要回源设计 | 比对首中尾、相邻肤色、真实世界光源 |
| 视频太短、首尾冗余、切点难衔接 | `production_plan` 和 G5：`Trim`、适用模式的 `Extend` 或补必要反应镜／声音桥 | 整数组剪辑验收；镜内通过不能替代场次通过 |
| 两项及以上核心维度失败 | 回到源头更正输入／拆镜，避免堆局部编辑 | 新试片有媒体后才更新验收状态 |

以上是**根据教程和 CineWeave 分工设计的修复决策**，不是各工具必然成功或对其余区域绝对不变的承诺。预设 `Emotion Wheel` 不替代真实表演评审；传统“加入颗粒、虚焦、手持”不能自动消除 AI 漂移。

### 六、原创小样工作演练：双人归还铜铃（仅方案）

**20 秒、16:9、两名成年角色、夜院一盏灯。** 角色甲准备把铜铃还给角色乙，乙最初拒绝，最终接过。镜头示例为 CineWeave 自写，并非 Higgsfield 视频里的故事／已生成片段。

- **资产组**：甲肖像身份参考、乙肖像身份参考各自独立；铜铃独立单件参考；夜院场景结构图和油灯光位。不要使用“甲乙两人合照”替代两个身份源。
- **S01（0–6 秒）**：共享中景，甲在画面左、乙在右，油灯固定于后景右侧；甲伸掌露出铜铃，摄影机固定，先让观众读懂距离和物的归属。出态：铃还在甲手中。
- **S02（6–13 秒）**：乙正面近景，甲的递铃手在画框左下角进入；乙先看铃，再避开目光，慢慢伸手，不能提前出现铃在乙手里。选定静止机位配人物动作，不靠甩镜制造戏剧性。
- **S03（13–20 秒）**：双手插入特写，乙握住铃、甲松手，铜铃在受控物理接触后唯一地转移到乙；摄影机轻微推近接点，随后停稳；铃声仅在接触／运动后出现。出态：铃在乙手，甲空手；下镜或结尾不再把铃放回甲手。

**路径选择**：S01–S02 可以尝试一段多镜候选，S03 的精确道具交接优先单独生成，必要时安排首帧锚点；20 秒成片不等于必须生成一条 20 秒视频。正式使用前依[镜头语言关卡](../routes/shot-direction.md)重审 S03 的镜头位置与运动是否有戏剧作用。验收：两张不同脸无混合、左右空间一致、油灯光向不跳、铃只转移一次、双手接触具可达性、时长与音源可剪。**此例状态 `design_only / pending_media`，未在 Higgsfield 真实生成。**
