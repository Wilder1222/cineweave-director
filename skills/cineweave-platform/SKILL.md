# CineWeave 平台适配

本能力是 `$cineweave-director` 统一入口工作流的内部步骤，接收明确子目标与原材料，完成本次职责后把完整稿件、完成范围和未决项返回入口。由导演核对原请求并统一交付，用户无需切换 Skill。

将已定内容投射到用户指定的入口，完成本次可用的复制稿与交接。普通工作稿无需建立完整项目、填写规范 JSON 或运行检查器；只读影响当前交付的章节。

本能力只拥有 `PromptProjectionPlan`（`cineweave_codex_prompt_projection_plan`）。母稿、故事、动作、镜头、能力档案与许可档案由其原责任领域维护；适配不能重新定义它们，也不替用户选择供应商。

## 从实际输入开始

继承原请求、同项目仍适用的决定与授权，读取完整图像／视频母稿、硬锁及可用参考。核对目标平台、模型版本、界面、模式，以及支持本次用途的能力／许可证据和查阅日期。参数请求值、界面解析值与实际返回值分别记录；未知保持未知。

只有摘要、文件名或来源声明时，不把它们当成已核对正文／媒体。没有母稿时，返回导演创作职责或交付围绕当前已给内容的限定待补稿；列出必需缺口，不自行创作整个新故事。缺能力、正式引用或参考图时继续可独立完成的忠实条件稿，依赖这些输入的提交结论保留未核验，不编槽位语法、时长档位或隐藏默认值。无需自动安装其他 Skill 或新增运行时。

## 镜头设计归导演母稿所有

平台投射应保留已批准机位、构图、摄影机静止／运动、焦点与切点；平台缺乏精确环绕或拉焦控件时注明兼容风险、将备选回流导演，不得默默重写为默认镜头。忠实既有稿转换不触发新创意选镜。
## 忠实适配与交付

1. **先整理可见内容。** 从源稿提取本图／本镜需要的可见与可听命题，保留身份、妆造、空间、表演、动作触发、关键接触／落空、结果、恢复与出入态。静帧保持一个选定瞬间；视频保持初态、主体与摄影机各自变化、可达终态、准确声音和相邻连续性。精简重复，不靠删硬锁或必要线索缩短。
2. **再组织平台方言。** 根据准确模型／界面／模式证据选择正文结构、原生控制与附件机制。实际图像已承担的外观可去重，未由其他输入承担的事实必须在稿中；图片未提供时只称待绑定，不假设首帧已有动作或道具。长度或复杂度超限时保留母稿，明确取舍及需回流的决定，不能无声删台词、改画幅、加速或改变动作。
3. **分开正文、参数与参考。** 参数给实际请求值及来源，界面值未知则标未知，不将叙事时长直接当模型档位。参考按身份、服装、场景、表演、运动、声音或风格限定职责与排除项；使用准确来源／选择器及已核验槽位，不把别名、上传说明或分镜板当原生首尾绑定。正文不夹带未声明参数、额外参数尾或私有定位符。
4. **对照母稿完成交接。** 交付完整独立复制稿、必要界面设置、参考职责与定位占位表、兼容性状态及人工核查项。界面核对清单逐项写明平台、模型、界面、模式、能力资料来源与查阅日期；未提供的值明确写未知。区分可填写控件与模式说明，不把资料标签当额外控件。用户只要提示词时，以一条完整正文为主，不用分析、示范或“同上”代替全文；需要分开附件或设置时在正文外说明。保留待补输入、适配取舍、完成范围与上游修订责任，不把局部通过写成全部任务完成。

局部修订已有适配稿时，只传播授权变量与必要版本变化，保留未影响字句。原稿若已有独立复制上下文不足，单列其来源缺口与另修范围，不以补齐上下文为由无声扩大本次修改；它仍是有未决项的工作稿。逐镜新编译按每镜独立稿交付，母稿要求的准确台词在相应稿内完整保留。

能力未核验时交付可审阅条件稿；只有依赖的能力、权利和兼容关卡通过，才称“可直接提交”。官方证据优先支持语法和模式，社区材料只能启发组织与试验；随包指南保留原核验日期，版本／界面变化或证据过期时复核。能力测试夹具与规范示例都不能证明当前账号或在线服务支持。

## 创作约定

- 默认**简体中文**，包括正负向提示词、变体、复制稿和交接；给定台词、字幕、标题、专有名称逐字保留。其他语言只按明确要求生成，机器字段、路径和命令保持原样。
- 用户事实、硬锁与已批准上游事实优先。平台限制、参数、参考槽位、代码、界面默认及适配丢失项只记录在适配结果，不能反向写入 canon、`PromptRecord` 或 `ImagePrompt`。源稿有矛盾时返回责任领域修订，再适配准确新版本。
- 同项目继承适用决定；[明确独立的任务](references/core/operating-model.md#任务范围与上下文)只使用本次输入及明确允许复用的材料。前案原创人物、场景、光源、素材或批准状态不能补作当前已提供事实。
- [观察、权利与批准](references/core/reference-evidence-and-rights.md)分别记录。参考声明不等于实际观察，审阅不等于用户批准，创作授权不等于向供应商传输、发布或训练许可；未知只阻止依赖它的最终确认，不妨碍限定草稿。
- 止于人工外部交接：不调用生成供应商、上传参考、导入画布或宣称已生成、发布。结构、参数、哈希与规划检查不证明真实执行或媒体质量；只有实际可访问的图像／视频／音频才支持相应验收，缺项不造任务 ID、回执、seed、哈希或成功声明。

## 可选规范交接

仅在用户要求规范 JSON 或已有系统需要时，读取[契约索引](resources/contracts/index.json)、[PromptProjectionPlan schema](resources/contracts/schemas/prompt-projection-plan.schema.json)及[规范示例](resources/contracts/examples/prompt-projection-plan.json)，逐字复用现有字段、枚举与边界；示例身份、批准和能力证据是夹具。精确绑定源母稿、`CapabilityProfile`、`LicenseProfile`及实际正文，不暗解 `latest`，不造 ID、版本、哈希或 `skillReceipt`。`ImagePrompt` 本身没有规范 ID／version；缺外部准确引用时保留工作引用和未核验状态，不为填引用改造母稿。`@Asset` 只经指定准确注册表解析。

规范复制稿按[内部闭合规则](references/optional/video-platform-adaptation.md#复制稿的内部闭合)检查：`promptBody` 与 `renderedPrompt.body` 逐字符相等；参数 ID／order 唯一，按 order 渲染一次，参数尾用 ASCII 空格连接，`copyText` 等于正文及有条件的单个 ASCII 空格与参数尾。不得 Unicode 归一化或改准确文案。方言语法仅依已定义证据；这项装配规则不能外推所有平台。检查正文和最终复制稿没有额外 flag、私有本地／file 定位符、凭据或签名私链。

绑定 ID／占位符与正文 `REF_` 声明闭合；附件占位可在旁路表。同名参考类别的数量与互斥关系按精确界面证据判断，不一律当单素材槽。能力／许可未知时保留 `unknown` 和相应未就绪状态，不用结构通过提升为 `ready_for_human`；已有实际媒体的限定评审也不补造缺失参数。所用检查器只记录真实运行结果，媒体验收仍需真实返回文件与证据。
