# 路由：参考证据（reference_evidence）

用于用户提供图像／视频、要求参考分析、需要有范围的迁移规则，或使用 `@Asset` 别名的情况。始终加载[参考证据与权利](../core/reference-evidence-and-rights.md)。

用户要找电影／电视剧、时代题材或真人／动漫方向时，按需从[影视作品参考库](../optional/film-television-reference-library.md)检索。目录的作品信息与原创迁移提案不能替代 `visible` 观察；具体造型、接触或镜头事实仍须实际媒体。参考分析完成后返回导演交付所需稿件，不止于片名列表。

## 流程

1. 确认媒体真实可访问，并说明用途。
2. 创建或接受精确的 `ReferenceAsset` 身份，不暴露私有定位地址。
3. 只将可见证据拆为原子观察。
4. 每项声明标记 `visible`、`declared`、`inferred` 或 `unknown`，并注明置信度。
5. 识别污染：源身份、服装、标志、文字、地点、构图、风格、裁切、修图或不确定元数据。
6. 评审是否适合目标及其权利范围。
7. 精确目标产物存在后，才创建 `ReferenceBindingSet`。

人物参考需分开：脸部身份、身体身份、形态、当前皮肤／材质状态、妆容、头发、服装、表情、姿势、拍摄、灯光、构图和表现方式。稳定身份进入人物领域，当前造型进入外观状态，表现方式进入风格，视点进入导演。

源到目标迁移要记录保留、替换、排除、允许变换、待决事项和验收证据。“用这张图”不等于迁移策略。

多参考合并前，先建立简短的来源／角色／迁移／排除表。用户指定身份、服装、风格角色，只授权对应迁移：默认排除服装图模特的脸和身体，也排除风格图的服装，除非另有要求。同图承担多个角色时拆成独立范围的观察。冲突按用户指定角色及已有目标锁定解决；只提出这些权威仍无法解决的重大歧义。

只有文字描述时，将其标为声明并提供暂定迁移计划，不能声称看过图片。最终提示词应检查是否漏入排除特征；计划本身不能证明生成身份一致。

参考精度由需要约束的决定确定：探索氛围可保持宽松，关键交接则明确姿态、持有和空间锚点。不能因参考含有某细节就锁定无关内容。只需布局时，可在授权范围内提出干净布局代理图，以排除无关身份和纹理；计划中的代理图不是已有资产。

场景多视图、调度图、色卡与服装状态分别按本次指定职责使用：布局与相对位置、行动路径、明暗／色彩关系、指定时段造型不能互相代替，也不自动锁定最终构图。调度图若明确以多个点位表示同一人的时间路径，应编译为一人的连续移动；若含义未说明则先核对，不能凭点数增加人数。编号、箭头与拼图排版不进入成片，除非用户需要图解或分屏。交付前逐一核对正文引用与职责表，修订后不能仍用旧图号指代另一角色或场景；语义未确定时保留待核绑定。

涉及梦境、换装或材质转换时，按情节划分参考生效范围，分别写出允许变化的表面／环境与需要连续的身份、身体位置、承托面和接触关系。只锁对目标必要的部分：原地连续转换可保留画面位置及接触压痕，明确允许跳切的换景则不强加同姿或固定机位。此处依据 [LibTV《毛茸茸·软着陆》画布](https://www.liblib.tv/creation/process?id=fc78047a749f42fe8fd0a5b0e33de748)于 2026-11-04 的设计文字作独立改写，未验证其实际转场效果。

连续候选出现劣化时，先与原始参考比较，再判断是否由迭代导致。保留来源链，指出实际变化，建议返回最干净且相关的权威来源，不把有缺陷的派生结果提升为正式设定。本节对 [Leos 参考控制讨论](https://github.com/MasterLeos/leos-six-department-directing-team-skill-v1/blob/2ed50edb3c7838fc9ffb68e50824e0ebff59c7d4/references/spatial-and-assets.md)作条件性改写，不保证更强控制或转换参考必然改善模型输出。

## 参考事实与目标造型冲突预检

人物视频先分开可见参考事实、已有角色硬锁和本次授权变更。核对发型、领口、衣色、表情、姿态等影响当前画面的属性；“参考原貌”必须有实际图像支持。文字要求与图片不同但已获授权时，明确写成目标造型替换，保留原图负责的身份特征；不要为了消除冲突擅自撤销换装、换发型或表演变化。重大歧义按既有权威解决后再编译，不能用“高度一致”掩盖。

照片不提供实际声线或未来表演。身份参考也不自动提供场景、目标服装和起始构图；全能参考不等于首帧锁定。需要目标定妆图时，将其列为有待制作／审阅的独立参考，限定职责，不把未验收的派生脸升为身份权威。无需重制资产的任务不强制增加首帧或多参考流程。

从失败案例吸收参考分工与验收方法，不复制该案例的脸、年龄、发型、衣色、场景、动作次数或固定秒点作为通用默认值。

## 画布结构与承接参考

研究社区项目时，按需读[画布学习方法](../optional/film-craft-study.md#从社区画布学习)。节点标题、分组、连线、提示词和作者说明只支持结构或设计分析；连线不自动说明实际输入槽位、剧情顺序、最终采用或生成成功。实际图像、运动、声音仍分别取得对应媒体再评；不能把设计文字登记成媒体的 `visible` 观察。只有清单时照样交付有范围的结构分析，不编造看过的内容。

跨段需要承接时，可提议使用已审阅片段中的合适截帧，记录精确源片段版本、帧号或实际时点、选取理由及传递的站位、持物／接触、遮挡和光色状态。节点名“尾帧”或视频→图片→视频的连线不能代替这些核对；来源帧位置未知时明确待核，不能默认最后一帧。截帧只承担约定的连续性范围，身份、产品结构和已有硬锁仍回到各自权威；检查派生帧的错误，不把缺陷继续固化。此路径不强制单镜任务增加截帧链，也不证明目标入口支持相应绑定。

## 别名规则

别名通过已提供的精确 `AssetAliasRegistry` 解析，包含范围、版本及内容哈希。不能推断全局别名、归一化成另一个资产或选择最新候选。

## 平台适配绑定

平台适配只能通过精确 `ReferenceObservation` 引用使用参考，包含一个有类型的角色、保留清单、排除清单和由人工确定的外部定位占位。账号个性化、情绪板和平台风格码属于适配状态，不是视觉证据。提交过定位地址或代码，并不证明输出保留了预期角色。

## 质量关卡

每条观察一个主角色；源和选择器精确；可见事实与推断分离；迁移与排除项不重叠；阻止身份／地理污染；权利按用途判断；不可访问媒体不能描述为已经观察。

可选规范输出（仅在请求结构化交接时）：`ReferenceAsset`、`ReferenceObservation`、`ReferenceBindingSet`、`AssetAliasRegistry`。

需要影视风格库的真实图片时，按需读取[剧照索引](../optional/style-still-references.md)对应组：35张色彩卡、25张真人妆容卡和8张动画人物画法卡，共78个高清参考文件；色彩与人物分开。实拍只收合格剧照；动漫场景按用户要求只选官方海报／主视觉或来源可核对的具名代表场面，海报只作美术配色参考，不证明正片调色。没有合格图片的模块不进入当前目录；实拍不收海报；所有模块不收低清、错配或无用途拼图，替代作品必须逐模块视觉匹配，不能仅凭题材、名气或像素数入选，保留来源页与原图链接；先检查实际图像，不把索引观察或妆容设计当作当前媒体已验证。
