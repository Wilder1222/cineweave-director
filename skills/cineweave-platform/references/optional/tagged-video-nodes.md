# 可选参考：所有创作节点的类型化标签

生成节点化资产、分镜、视频、音频、剪辑或评审时加载。这是供人编辑的工作表写法，不是新增根契约，也不是平台导入／接口数据结构。它与平台无关的正式设定保持分离。精确翻译只改变语言，添加标签不授权换风格或改台词。

## 语法与范围

使用成对标签，每类一块，例如 `<运镜>摄影机保持眼平，缓慢前移，终点停稳。</运镜>`。节点 `prompt` 的全部内容必须位于受支持标签内。不能嵌套或重复同名标签；多位说话人和多条提示放在同一块中。文字中的 `&`、`<`、`>` 分别转义为 `&amp;`、`&lt;`、`&gt;`，检查器只解码一次，不改准确文案。普通引号和换行保持。

每个节点都有 `<节点>`（准确工作表 ID）、`<目标>`、`<约束>`；再按类型增加对应标签，不给每个节点塞同一张四十字段表。不相关表演项可以省略，不能为填表编出脸、对白或特效。确有意义的“没有”可以写明，例如 `<特效>本镜头无叙事特效。</特效>`。

只读[检查器](../../scripts/check-video-plan.mjs)拥有 v1 工作表支持的标签／类型词汇，检查语法和输入算术，不判断电影含义。这些标签不是所宣称的平台原生控制符，不能把未支持语法冒充官方接口。

人物的肌肤、发饰和仪态可在 `<外观>`、`<发型>`、`<表演>` 等适用标签内展开；场景类型、色调、结构与样式在 `<场景>`、`<空间>`、`<光线>`、`<材质>` 内展开。标签最少数量不是内容完整性标准，按[细节规范](prompt-detail-standard.md)逐项核对。

## 各类型的最少标签

叙事视频的 `<运镜>` 必须反映导演已确定的机位及摄影机固定／移动决定。允许写“固定机位，焦点保持于角色”，不能机械要求每镜运镜；若移动则说清触发、路径、快慢及出点；移焦独立说明焦点平面，不只贴“环绕”“甩镜”等词。
## 各类型的最少标签

除通用标签外：

| 工作表类型 | 必要标签 | 常用可选标签 |
| --- | --- | --- |
| `brief` | 项目、目标、约束 | 画幅、时长、情绪 |
| `storyboard` | 分镜、时间线、衔接 | 运镜、情绪、声音 |
| `character_image` | 主体、外观、构图、光线、质感 | 身份、服装、发型、妆容、表情 |
| `scene_image` | 场景、空间、构图、光线、材质 | 环境、画幅 |
| `prop_image` | 主体、形制、材质、构图、光线 | 参考、排除 |
| `reference_map` | 参考、排除 | 身份、保留、版本 |
| `first_frame` | 参考、首帧、构图、光线 | 情绪、表情、眼神 |
| `last_frame` | 参考、尾帧、构图、光线 | 情绪、表情、眼神 |
| `video_t2v` | 起态、动作、运镜、终态、时长、剪辑余量 | 主体、场景、构图、光线、声音 |
| `video_i2v` | 参考、首帧、动作、运镜、终态、时长、剪辑余量 | 表演、情绪、表情、台词、声线、特效、时间线 |
| `video_flf` | 参考、首帧、尾帧、动作、运镜、时长、剪辑余量 | 情绪、表情、台词、特效、时间线 |
| `video_reference` | 参考、起态、动作、运镜、终态、时长、剪辑余量 | 情绪、表情、台词、特效、时间线 |
| `video_extend` | 参考、延长边界、动作、运镜、终态、时长、剪辑余量 | 台词、环境、声音 |
| `video_edit` | 参考、修改范围、保留、验收 | 运镜、表情、特效 |
| `dialogue` | 台词、声线、语气、情绪、时间线 | 字幕、节奏 |
| `sound` | 音效、空间、时间线 | 节奏、声音 |
| `edit` | 时间线、衔接、字幕 | 声音、验收 |
| `review` | 证据、验收 | 修改范围、保留 |


`<情绪>`描述戏剧情绪轨迹，`<表情>`描述可见面部变化，`<台词>`保留准确口播原文，`<语气>`指导声音表达。四者分开。`<光线>`写光源及响应，`<质感>`／`<材质>`保持共同视觉基线。特效或参考不授权改变身份。

`video_t2v` 的起态由文字设计，不要求虚构首帧图片；平台能力作用域使用 `mode: t2v`，依然检查时长、摄影机控制和声音提示。若需要实际参考约束，选择匹配的图生视频或参考模式，不能只改类型来绕过绑定。

`video_reference` 可以仅绑定身份／场景／表演或分镜板，不要求 `first_frame` 或 `last_frame`。静态分镜板使用 `roles: ["storyboard"]`，在 `transfer` 中写明格位到镜号或动作阶段的映射，`exclude` 排除边框、编号及不迁移内容；工作表仍使用 `mode: multimodal`。这是本地只读检查器的职责名，不是平台参数或新增根契约字段；它只检查图像类型，不识别真实画格与时序。

纯文字多镜使用 `video_t2v`，带全能参考或整板的多镜使用 `video_reference`，通过已有 `<分镜>`、`<时间线>`、`<衔接>` 展开镜号、时间、切点与状态。单镜／多镜是内容组织，不另造供应商模式名；同一字段中的多个镜头应连续写出，不重复同名标签。参考图制作方案使用 `storyboard` 节点说明版式、逐格构图与映射，相关详细视觉信息放在相应标签内。检查器接受该结构不证明平台支持一次生成多镜。

## 三层编写结构

1. **项目层：**世界、人物、场景、风格事实，批准后的台词、制作意图、权利与全局锁定。
2. **节点层：**只含必要继承事实、精确参考和所选时间单元的详细标签母稿。
3. **提交适配：**真实附件、原生模型控制和适配提示词；记录各标签保留／改写后去了哪里，不能为缩短而丢硬约束。

检查器的 `plainTextPreview` 保留所有标签对应的说明，供人工比对；它**不是直接提交稿，也不能送入语音合成**。配音只取权威口播 `text`，受支持时另给声线与语气控制。元数据、时序、说话人标签及舞台说明不能变成口播。字幕策略单独决定，不能全局禁止有批准招牌或标题的镜头出现文字。

## 首尾帧示例

原创演示，不是项目正式设定。

```text
<节点>SH05_FIRST</节点>
<目标>为递灯动作提供尚未完成的起点。</目标>
<参考>角色、服装和街景分别绑定已选版本；此处为待绑定示例。</参考>
<首帧>女子正面站立，右手灯笼位于腰侧，手腕与灯柄接触清楚。</首帧>
<构图>视点对应对面人物，完整保留递灯所需的前方空间。</构图>
<光线>继承该场景照明；脸部可辨，灯笼局部暖光不改变全画面白平衡。</光线>
<表情>嘴唇自然闭合，视线落在对面人物。</表情>
<约束>保留相貌、服装、路宽和背景建筑；不要把灯笼提前递到终点。</约束>
```

```text
<节点>SH05_LAST</节点>
<目标>提供递灯后可保持的终态参考。</目标>
<参考>沿用首帧相同角色、服装、场景和道具版本。</参考>
<尾帧>右臂已向前递出，手仍持灯柄；不新增接灯人的手。</尾帧>
<构图>继承轴线和背景位置，镜头仅到达已设计的推进终点。</构图>
<光线>光源和整体色彩关系不变；灯移动引起的局部光变化符合位置。</光线>
<表情>话已说完，唇部闭合，轻微笑意保持。</表情>
<约束>这是图像终态目标，不是视频已在剪辑出点前到达此状态的证据。</约束>
```

完整视频／对白／剪辑例子见配套工作簿。路径和能力明确为夹具，不宣称例子文件已经上传、查看、生成、批准或导入。

## 只读工作表检查

需要算术或结构检查时运行 `node <skill-root>/scripts/check-video-plan.mjs worksheet.json`。普通 Skill 使用不要求安装 Node；没有环境则做可用检查并披露未运行项。合法工作表仍可有未决参考和能力；`declarationComplete` 只描述给定字段是否齐全，`capabilityVerified`、`mediaVerified` 保持 `false`。

工具检查标签、必填字段、节点 ID、缺失依赖与环、参考角色和重复、声明的参考数量上限、模型／界面政策不匹配、终点与余量冲突、有理数时长选择、提示时间、准确台词副本及同一说话人的语音重叠。它不理解参考像素、不检测所有语义矛盾、不核验权利、不测语音、不保证时间遵循，也不能认证官方平台导入。
