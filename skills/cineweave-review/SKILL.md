# CineWeave 评审与修复

本能力是 `$cineweave-director` 统一入口工作流的内部步骤，接收明确子目标与原材料，完成本次职责后把完整稿件、完成范围和未决项返回入口。由导演核对原请求并统一交付，用户无需切换 Skill。

完成本次声明范围的评审和最小修订，按[评审路由](references/routes/review-repair.md)选择所需领域资料。普通草稿或局部问题只检查相关维度，无需建立完整项目或规范 JSON。

本能力拥有 `ControlBenchmark`、`ControlBenchmarkReview`、`CreativeReview`、`RepairPlan`。评审结果不批准素材、修改 canon 或制造生成证据；故事、人物、场景、动作、镜头和平台适配仍由各自责任领域维护。

## 先确定可观察范围

读取真实评审对象、完整原稿、用户硬锁和必要相邻来源。文稿可检查完整性、矛盾、时序和交接；实际可访问的图像、视频、声音才支持对应媒体验收。只有文字描述或预期结果时给条件诊断及可区分解释的检查办法，不声称已看过媒体。

元数据缺失仍可完成有限画面评审；来源、参数、许可及不可观察维度保持未知。单帧不证明运动或声音同步，单镜不证明整场连续。给精确对象／版本／区间、期望、实际观察、依据、状态与严重性；没有准确引用时使用工作引用，不造 ID、哈希、任务回执或旧批准。

使用既有 `pass`、`warn`、`fail`、`unknown`、`not applicable` 展示语义；规范枚举以实际 schema 为准。严重性为 `advisory`、`important`、`blocking`。阻断问题单独列出，不能被整体美感平均；用户偏好与技术／权利合格性分别判断，不评颜值或生物识别身份。

## 摄影语言专项审查

新创作的正式叙事镜头组必须在 `cinematography` 检查景别／机位／构图、固定或运动、焦点、触发、预期可见变化和出点。新规范工作表声明 `source.cameraLanguageScope` 和 `cameraDecisions` 并校验逐镜覆盖；历史工作表、静态资产和翻译保留原有范围。真实运动效果需另看媒体。
## 按范围检查与修订

综合设计／提示词评审、完整场次定稿或镜头组正式制作／规范交接，读取[群像与逐镜评审](references/optional/ensemble-direction-and-review.md)，覆盖六视角 × 本次声明镜头。完整六视角评审在 Node 可用时整理工作表并实际运行本包的[逐镜检查器](scripts/check-shot-review.mjs)；没有 Node 时完成手工评审并记录限制。局部请求只检查所选维度，采用工作表且 Node 可用时也必须实际运行。分别检查 `valid`、`coverageComplete`、`reviewComplete` 与未决项，记录真实结果，不以计划运行代替执行。

视频规划、台词和时长工作表按需运行[视频检查器](scripts/check-video-plan.mjs)；字幕／交付时间读[交付检查器](scripts/check-delivery.mjs)。它们只检查声明和运算，不观察媒体或证明平台、接触、表情、音画同步成功。普通人工草稿无需为检查器补造整套数据。

先做能够区分候选根因的检查，再按[诊断对应章节](references/optional/generation-diagnostics.md#诊断索引)回到负责领域。一个修复只改变一个领域内的一个根因变量，保留已通过部分，列出下游重编译后果及相邻连续性检查；不能把摄影机、光源、动作或身份的多项改动包装成一次修复。

需要实际修订文本时给完整可用稿，未受影响的段落与准确文案保留原文。修订创建新候选或子版本，保留原稿与既有批准记录，不原地覆盖已批准版本；修订及评审通过不自动授予批准。新媒体仍须由授权的外部流程取得；只提供修订稿或计划不能宣称已修复返回 Take。一个修订候选后停止并复查；多领域问题按依赖方向拆开，遵循用户上限，同因重复失败且没有新辨别证据时保留未决原因和可撤销替代。

## 创作约定

- 默认**简体中文**，保留给定台词、字幕、标题和专有名称；机器字段、路径、枚举及命令保持原样。
- 用户事实和硬锁优先。同项目继承适用决定；[独立任务](references/core/operating-model.md#任务范围与上下文)只用本次原材料及明确允许复用的来源，不带入前案设定或未提供的通过结论。
- 分开文本检查、规划检查、真实媒体观察与用户批准。权利／肖像／传输／发布按用途判断，缺证据保留未知；哈希只证明字节相同。
- 不调用供应商、上传、导入、自动安装或宣称生成／发布。局部通过只覆盖实际检查范围，不提升为整个项目、平台能力或媒体验收通过。

## 交付与责任回流

交付证据与问题、保留项、根因与最小变量、所需修订稿、复查及停止条件。正式基准在观察前定义，不用看到的结果倒填通过门槛；实际评审保留首轮失败与旧版本。只有媒体的文字描述或预期结果时交付条件诊断和验证方法；已有真实文稿可完成直接文本评审及所需修订，对应媒体验收保持未知。

跨阶段请求由宿主实际发现的 `$cineweave-director` 统筹；平台遗漏由 `$cineweave-platform` 修投射，参考职责由 `$cineweave-reference` 修观察／绑定，上游决定由导演修订。默认同一代理按需读取准确入口，传入完整原稿与证据，返回问题和责任，不让评审反写上游硬锁。专业入口缺失时恢复导演的 `review_repair` 内联路径并说明实际采用路径；不猜兄弟目录或缓存版本、伪称已调用。导演也缺失时完成限定评审并列待补依赖。

范围或权威冲突按需读[产物控制](references/core/artifact-control-and-precedence.md)，跨稿修订读[变更影响](references/optional/drafts-and-change-impact.md)，源版本与相邻状态读[连续性](references/core/visual-bible-and-continuity.md)。只加载影响当前问题的章节。

## 可选规范交接

用户要求规范 JSON 或系统交接时，从[契约索引](resources/contracts/index.json)读取本能力四类 schema 与示例，复用准确 kind、字段、枚举及引用规则。完整共享分发不增加产物所有权；示例批准、能力和媒体证据均为夹具。缺准确来源时保持工作稿，结构通过不等于真实证据通过。
