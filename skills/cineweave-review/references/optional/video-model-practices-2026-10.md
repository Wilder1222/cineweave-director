# 视频模型实践：Seedance 2.5、Kling 4.0 与 Wan 3.0

核查基准：Seedance／Wan 为 2026-10-31，Kling 4.0 用户指南和开发者目录补查至 2026-11-02。可灵新资料本次可读官方搜索索引正文；直接打开指南超时、开发者目录只返回应用壳，故下述新增 UI 信息限于索引所示，不代表目标账号实测。快手 4.0 公告发布日期为 2026-10-17；Wan 3.0 提示词指南标注更新于 2026-10-16；火山引擎页面以查阅时可访问内容为准。参数变化时重新核对对应模型、任务和入口。

## 先决定生成路径

同一段故事先确定观众需要看到什么、人物和道具的初态与出态、动作因果、镜头覆盖、相邻镜头的空间与声音承接。再选择文生、首帧／首尾帧、参考生成、编辑或延长；素材上传、模型参数和提示词是不同层次。多镜一条生成可用于试拍或节奏草图，关键动作、接触、表演与转场仍需看实际成片。严格控制身份、道具或剪辑点时，可拆镜生成并留出衔接余量；不要把总时长上限当作推荐镜头长度。

## 模型写法与创作判断

### Seedance 2.5

用「主体＋动作／事件＋环境＋风格＋运镜／切镜＋声音」表达需要控制的内容。`@图片1`、`@视频1`、`@音频1` 对应上传顺序并写明各自用途，例如身份、场景、动作或音色，不把别人的脸或无关背景一起迁移。多人素材按出场次序组织，一一绑定角色。音乐可用 `()`、音效用 `<>`、台词用 `{}`、字幕用 `〖〗`；不需要的声音或字幕明确写出。

方舟 API 的 `generate_audio` 默认 `true`，可生成与画面同步的声音；全片要求完全无声时设置 `false`，并在收到文件后检查实际声音。若只是无对白但需要雨声、门轴声或音乐，保留有声生成并在正文指定需要和禁止的声音，不要误关整个声轨。以上是[方舟创建任务接口](https://docs.volcengine.com/docs/ark/create-video-generation-task-api?lang=zh)范围；其他界面核对对应控件，不能假定字段同名。API 交接按该接口准备 JSON 内容类型与认证头，密钥留在调用者的安全环境；创建任务后记录实际任务 ID 并按官方接口查询终态，未知提交结果不盲目重复创建。提示词、设置和任务记录分别交付，不虚构任务或音频结果。

**方舟输入组合与任务类型。** 方舟 Seedance 2.5 API 的首帧、首尾帧及全模态参考（含图、视频或音频参考）是互斥场景。若要求同次严格 `first_frame` 加运镜视频或音频参考，应保留冲突并给条件备选：严格首帧路径失去同请求的原生额外参考；全模态参考路径可在正文提出参考图作为起始画面的意图，但不保证严格首帧一致。列出实际素材、绑定及损失，未经选择不擅自改变目标。其他服务的组合规则分别核验。

方舟全模态参考任务的 `omni_reference_task_type` 默认 `auto`，会结合素材与提示词判断参考生成、编辑或延长。含参考视频且固定目标时长时，若实际被识别为编辑，编辑要求 `ratio=adaptive` 和 `duration=-1`，固定时长可能导致异步约束错误。明确要基于参考新生成时，方舟接口可按文档指定 `reference` 以提前检查该任务的参数；实际处理仍会判断提示意图，不一致可能异步返回 `InvalidParameter.TaskTypeMismatch`，不是成功保证。编辑和延长各按其实际约束与素材选择配置；字段不推广到其他入口，仍须查询实际任务终态。[方舟任务 API](https://docs.volcengine.com/docs/ark/create-video-generation-task-api?lang=zh)。

**方舟 API 输入文件核验。** 已确认入口为方舟 Seedance 2.5 API 且用户需要执行条件时，按本次实际输入的类型逐文件交接下列限制、来源和待核结果；文件未知只列标准及待核项，不能声称已合格。编辑与非编辑的单视频时长分别核对；任务类型未知时保留两类条件。下列 MB 沿用原文单位，不自行换算为字节。

| 输入 | 方舟 Seedance 2.5 API 官方条件 |
| --- | --- |
| 图片 | jpeg、png、webp、bmp、tiff、gif、heic、heif；宽高各 300–6000 px，宽高比（宽／高）0.4–2.5；单张小于 30 MB。首帧／首尾帧与参考场景的数量和互斥按上文。 |
| `reference_video` | mp4／mov 容器，输入分辨率档为 480p、720p、1080p、4k；单段非编辑 2–30 秒、编辑 4–30 秒；宽高各 300–6000 px，宽高比（宽／高）0.4–2.5，总像素（宽×高）407696–8295044；单段不超过 200 MB、24–60 fps；最多 10 段且合计不超过 30 秒。视频编码另按官方支持表核验，容器格式不等于任意编码均支持。 |
| `reference_audio` | wav／mp3，单段 2–30 秒、不超过 15 MB；最多 10 段且合计不超过 30 秒。 |

以上区间含端点；官方还列请求体不超过 64 MB，Base64 会计入请求体。编辑必须有参考视频并核对 `ratio=adaptive`、`duration=-1`；视频与音频数量、总长分别计算，图片与视频其他尺寸及素材准入按[方舟 API](https://docs.volcengine.com/docs/ark/create-video-generation-task-api?lang=zh)逐项核对。不能将这些接口条件推广到其他界面或账号。

镜头可用序号或整数秒时间戳组织。官方建议宫格少于 15 格、线稿简洁，补写动作和运镜；它提供剧情方向而非逐格严格对齐。要求更接近指定画面时，将独立图按顺序作为关键帧输入，并在首句说明图片顺序。

参考素材上限、主体数量和经验建议是不同概念。方舟提示词指南建议：主体音视频参考覆盖 1–5 个主体、主体图参考覆盖 1–8 个主体时通常更稳定；这说的是人物、物件或场景等**不同主体的数量**，不是文件数量限制。一张图可能包含两名人物，同一人物也可能有多张图；仍须逐一绑定素材与主体。1–5 个主体时可用单视图或多视图；超过 5 个主体时官方称单视图一般更稳定，如需多视角可拆成不同图片。主体音视频参考的 5–10 秒是经验建议，视频编辑源片 20 秒以内及编辑时 1–5 张参考图也是质量建议而非硬性上限；仍以当前入口的素材规则、源片完整性及实际样片为准。[方舟提示词指南](https://docs.volcengine.com/docs/ark/seedance-2-5-prompt-guide?lang=zh)。

方舟编辑输出时长是与源片**基本**对齐而非精确保证：模型教程称帧处理可能使输出略短，最多约 0.4 秒；提示词指南另称最大约 0.3 秒，并对特定来源另作说明。两个数字有差异，不能当作任何片段的实测误差。收到媒体后测量实际采用区间、帧率和声画时间映射，再计算补时或检查指定编辑区间；不能以输入长度推定返回长度或直接断言补齐秒数。参见[模型教程](https://docs.volcengine.com/docs/ark/seedance-2-5?lang=zh)与[提示词指南](https://docs.volcengine.com/docs/ark/seedance-2-5-prompt-guide?lang=zh)。

把此范围同时写进复制稿外的设置表和执行交接：例如“画幅沿用待编辑视频；输出时长与其基本对齐，实际文件需测量”，不能在表中简写为“继承画幅与时长”而在正文又承认可能缩短。编辑采用 `duration=-1` 不保证输出恰为源片长度或用户目标时长。

方舟 API 文档说明 Seedance 2.5 不支持直接上传含真人人脸的参考图／视频；平台另列指定模型产物、预置虚拟人像及已授权真人素材等渠道。适配涉及未观察的参考图／源视频时，将这条方舟接口限制和可用渠道的待核条件直接告知，而不只写“检查素材准入”；不得推断未知素材一定含或不含人脸。上传前按当前[接口文档](https://docs.volcengine.com/docs/ark/create-video-generation-task-api?lang=zh)和[真人素材录入指南](https://docs.volcengine.com/docs/ark/upload-real-person-portrait-assets?lang=zh)核验适用渠道、账号条件与授权，不将限制泛化为其他平台或所有含人脸结果。

**条件稿 A：仅文字，12 秒，多镜。** 在支持文生的入口选 12 秒；以下是完整正文：

```text

```

**条件稿 B：首帧图。** 仅在实际首帧显示室内检票台后的站务员、可擦到的雾玻璃、窗外手提灯，且斜侧机位能看清她的右手与脸侧时使用；左手及钥匙若不在画内，本稿不依赖钥匙。上传后在入口指定为首帧，条件允许时设置 8 秒；不要把参考图上传当成首帧已锁定：

```text
从给定首帧开始，雨夜旧车站，站务员站在室内检票台后，面前雾玻璃外是站台上的手提灯。室内斜侧中近景保留她的脸侧、右手和玻璃外的灯；摄影机沿玻璃内侧缓慢靠近，在玻璃前停住。她用右手抹开一小片水雾，看到灯轻晃，手停在玻璃上，目光从手移向灯。她随后收回目光，脸侧露出警觉的神情。焦点先落在手，再落到玻璃外的灯，最后回到她的眼睛；室内暖光和站台冷雨光保持连续。<雨落在顶棚上，灯具轻响> 无对白，无背景音乐，无字幕。
```

**条件稿 C：多参考。** 仅当素材确实存在、所选参考模式支持图／视频／音频组合，且图片2的车站允许室内检票玻璃、窗外站台和室内门构成可通行关系时使用：图片1是站务员身份与服装，图片2是车站环境，视频1是缓慢推镜动作，音频1是背景音乐；按各类别上传顺序绑定，12 秒。本稿意图是参考生成新片；方舟 API 可按上述条件选择 `omni_reference_task_type=reference` 并核查异步终态，不能把字段当作必然成功。实际素材不满足时先调整镜头或参考，不能虚构已核对的空间。

### Kling 4.0

按[可灵 4.0 官方用户指南](https://kling.ai/quickstart/kling-4-model-user-guide)组织创作：先写素材职责，再写主体、动作、空间、镜头及声音；对上传后实际出现的 `@Image1`、`@Video1` 等标签明确参考什么、排除什么。指南示例支持用文字编排镜号、时间和运镜，但时间是创作意图，不保证精确切点。以下信息来自 2026-11-02 可读的**官方搜索索引正文**，直接页面本次打开超时；具体账号、地区及其他平台以实际入口为准，不能将此 UI 语法或参数直接当作 API 字段。

- **入口选择：**指南将 Omni Reference 和独立 Keyframes 列为不同入口，并将两个入口及其能力表述为不能在同一任务合并；但其示例与官方专题又讨论关键帧和 Omni 参考协同，不能据此断言某一入口内任意具体组合已支持或必不支持，具体绑定方式需核验，见下项。Omni 面向图、视频与声线参考，也提供文生及关键帧到视频工作流；独立 Keyframes 入口用于按时间安排图像关键帧，只支持图像输入，上传后画幅随第一关键帧。不要把“Omni 也能做关键帧视频”误写成任何严格关键帧都能与视频参考同次叠加，也不要把图片参考自动称为已锁定首帧。
- **同任务绑定方式待核：**指南的独立 Keyframes 规则说不支持参考素材，但该节一个首帧示例又同时出现 `@Video1`；另一篇[可灵官方关键帧专题](https://kling.ai/blog/kling-4-multiple-keyframes-guide)称多关键帧可与 Omni 参考协同，却未消除两个独立入口的说明。需要严格关键帧加视频动作参考时，同时提出“实际入口验证后尝试同任务组合”和“不支持时分入口／分任务”的条件方案，写出各自输入、控制损失与待核项；不能只凭示例断言两入口已合并、同次绑定已成功或分任务是唯一可能。
- **冲突的交接内容：**用户明确要求严格关键帧加视频参考时，在交接正文就近逐项说明：[4.0 用户指南](https://kling.ai/quickstart/kling-4-model-user-guide)将独立 Keyframes 写为仅图像输入、不支持参考素材，并称两个入口及其能力不能在同一任务合并；同一指南该节的首帧示例却使用 `@Video1`；[官方关键帧专题](https://kling.ai/blog/kling-4-multiple-keyframes-guide)又称多关键帧可与 Omni 参考协同。标出这些来源尚未消解的冲突及实际入口待核，不能只写“官方资料有差异”，也不能断言该具体组合已支持或必不支持。保留用户的同次目标和未经采用的条件备选及损失。
- **Omni 素材与声音：**图、视频、声线档案和元素合计最多 15 项；图最多 10、视频最多 5 且视频合计最多 30 秒、声线档案最多 3、元素最多 7（其中视频元素最多 3）。参考视频、编辑视频及视频元素共享最多 5 段、总时长 30 秒的额度；这些数字均是指南所述入口的上限，不等于应填满。`elements` 是素材类型，不等于角色人数。音频输入限声线档案；背景音乐和音效不能按该指南作为音频参考上传，应以文字说明或在经选择的后期处理。若要求将某声线用于没有画内说话人的画外旁白，须核验该入口是否支持这种绑定及操作方式，不能仅由支持声线档案推断旁白绑定已可用。
- **Omni 视频执行交接：**官方指南所述工作区的参考／编辑视频每段 3–30 秒、每段不超过 300 MB、宽高比在 2:5 至 5:2；共享视频配额上限和总时长仍按上一项核对。用户要求执行条件时，连同该模式、片数、单段与总时长、文件大小和比例写入待核清单，按真实文件逐项检查；输入、账号或实际界面未知时不声称满足。其他入口或 API 规格需另查。[可灵 4.0 用户指南](https://kling.ai/quickstart/kling-4-model-user-guide)。
- **声线不可用时的完整交接：**若本次提出“只用产品图生成画面，旁白和现有音乐在后期制作”的备选，除说明授权、声线与音乐的外部制作及损失外，另给只依赖产品图的完整可复制视频稿：保留场景、产品动作、机位和时长，写明生成画面无对白、无背景音乐，不引用未绑定的声线档案。精确台词在旁路旁白交接中逐字保留；外部配音工具是否支持目标声线、实际混音和授权仍需核验。不能让用户从包含声线绑定的主稿中自行删除一部分，或只给一句“先生成无声画面”。
- **分镜与版本：**指南称所述工作区的多镜头／Smart Storyboard 及音画同步默认启用且无独立开关；不要让用户寻找一个未经证实的开关。要求单镜时在正文明确连续动作、固定或所需运镜与无切镜，实际结果仍要检查。Kling 4.0 Flash 的指南上限为 20 秒、720p，且不支持首尾帧配对或多关键帧；不要把这些限制无差别套到标准版。指南规格表列 4K 和 HDR，概述却将相关 10-bit HDR 描述为即将推出；发布公告对分辨率也有将来时表述，因此开放状态按实际入口核验，最终以文件元数据为准。
- **交接时保留入口归属：**用户入口未知时，不要仅写“该入口支持／不支持”或把指南界面的行为写成所有入口通用。每项能力与限制在交接正文中直接写出已核实的产品、工作区及模式：例如“官方指南所述创作工作区的音画同步默认启用且无独立开关”“官方指南的 Omni Reference 音频输入限声线档案，不接受背景音乐或音效文件作为音频参考”。7 秒选项也应限定为指南列出的标准 Omni Reference 或独立 Keyframes 界面，而非断言未知 API 或账号支持。其他入口、账号及版本须分别核验；这些描述不证明已生成声音或完成同步。
- **原片编辑与参考生成：**官方指南所述 Omni Reference 工作区中，实际绑定原片后，用 `Edit @Video1` 明确编辑对应视频，并逐项写需改变和需保留的内容；只写“参考 @Video1”可能表达为依据视频生成新片。实际标签以界面为准；未提供或未绑定的原片不能冒称已上传，保留项也须在结果中逐项核验，不假称原片无损或编辑成功。

### Wan 3.0

官方提示建议按总体描述、素材编号和职责、镜号与起止秒、动作与摄影、对白、声音和风格组织；生成指南给出每镜 4–6 秒的分镜参考，提示词指南建议每段 2–5 秒，两者是有差异的建议，实际节奏依戏剧动作与试片调整，不是 API 强制配额。图、视频、音频分别按各自上传顺序编号，例如 `Image 1`、`Video 1`、`Audio 1`；不要假定不同类型共用序号。无对白或无背景音乐应明确写出，省略时模型可能自行决定；若要求完全无声，还需在支持时关闭音频。多镜头描述应保持主体、空间、动作和气氛的承接。

选择首尾帧画面后期配音时，说明百炼 Wan 3.0 文档中的 API 默认生成音频、可用 `audio=false` 关闭，并按目标界面核对适用性后决定保留还是关闭原生音轨，避免重叠；声线参考不等于可直接混入时间线的完整对白录音。音画同步、声音授权及是否能保留所需环境音均需实际检查。

**文档／网页参考是独立路径。** 百炼 Wan 3.0 API 的 `file` 与 `link` 只能二选一，各最多一个；在文件／网页参考生视频组合中可与 `reference_image`／`reference_video`／`reference_audio` 组合，但与 `first_frame`／`last_frame` 同次请求互斥。同一 API 的视频编辑和延长模式列出的是 `reference_video` 与可选图／音频，未列文件或网页；不能仅凭文件参考模式允许 `file` 加视频，就断言“编辑原视频＋文件”在具体编辑模式可用，需按实际模式核验。文档或网页输入时必须设 `prompt_extend=true`，该设置会让模型改写提示词；逐字广告语、标识和对白仍须按要求独立核对，必要时在后期确定性排字。接口说明模型依据文件／网页内容生成视频，并未建立可供逐字校对的文本提取结果；若需要准确文本，应由授权人员或经核实且获准的文本提取工具取得并核对，不假称视频接口返回了原文。

中国站北京地域的 [Wan 3.0 API 文档](https://help.aliyun.com/zh/model-studio/wan3-video-generation-api-reference)列出 `file` 可使用公网 HTTP(S) URL 或通过官方上传流程取得的临时 OSS URL；[国际站模型文档](https://docs.modelstudio.console.alibabacloud.com/en/model-studio/wan3-video-generation-api-reference)当前仅列公网文件 URL，未列临时 OSS，其他地域依实际端点文档与验证处理。临时上传仍会把素材交给服务处理；不得擅自公开或上传内部文件。中国站的[临时文件说明](https://help.aliyun.com/zh/model-studio/get-temporary-file-url)对地域、模型、账号、有效期与 HTTP 请求头有约束，并提示临时存储不用于生产环境。`link` 需是可公开访问且无需登录的网页；账号、地区、文件权限或素材未知时保持待核，不宣称已读取或成功提交。若用户同时要求严格首帧与读取文件，应保留原要求，交付说明各自损失的条件备选，不把参考图称作严格首帧，也不默认改变要求。

**百炼中国站 Wan 3.0 API 输入文件核验。** 已确认该 API 入口且用户需要执行条件时，按本次实际输入类型逐文件交接[官方 API](https://help.aliyun.com/zh/model-studio/wan3-video-generation-api-reference)下列限制、来源和待核结果；素材未知不称已合格。MB 沿用原文单位，不自行换算为字节。

| 输入 | 百炼中国站 Wan 3.0 API 官方条件 |
| --- | --- |
| `first_frame`／`last_frame`／`reference_image` | JPEG、JPG、PNG（不支持透明通道）、BMP、WEBP；单边 240–8000 px，官方写长宽比不超过 8:1；单张不超过 20 MB。首尾帧与参考的互斥及数量按上文。 |
| `reference_video` | mp4／mov，单段 1–15 秒，单边 240–4096 px，官方写长宽比不超过 8:1；单段不超过 100 MB、至少 16 fps；最多 5 段且合计不超过 15 秒。 |
| `reference_audio` | wav／mp3，单段 1–15 秒、不超过 15 MB；最多 5 段且合计不超过 15 秒。 |

以上闭区间含端点；官方的“长宽比不超过 8:1”未明确横竖方向的计算约定，边界画幅须按目标接口核验，不自行假定 1:8 下界。视频与音频的数量、总长分别计算，并核对总参考数、尺寸比例、输入组合与文件来源。此处官方规格未将视频单段时长按编辑／非编辑细分，不套用方舟编辑下限；视频编码等未明确字段、其他区域或入口按其文档另核。含视频输入时，输出 `duration` 的总长规则与续写示例歧义仍按上表保留待核，不凭单文件合格推定任务已可执行。

单次请求互斥不自动等于整片无法完成：若用户未要求单次生成或一镜到底，可提出待选择的分次方案，例如首段以 `first_frame` 生成，后段在获准传输文件且模式可用时独立以 `file` 和参考图生成，再剪接并由授权人员核对、后期排入准确文案。第二段不是沿用首帧锁，也不能假称以文件参考模式完成了视频编辑；逐段素材、时长、成本及身份／空间／光线接缝须分别核对。最终成片首帧和文字须以实际导出验收；方案未经选择和素材授权不执行。用户锁定单次或单镜时，分次方案须明确违背的约束。

**条件稿 A：仅文字，12 秒。** 在 Wan 3.0 文生任务设置对应时长；正文：


**条件稿 C：多模态参考。** 仅在素材真实存在、车站参考允许下述室内路径且所选参考任务支持该组合时使用：按上传顺序 `Image 1` 为人物、`Image 2` 为车站、`Video 1` 为运镜参考、`Audio 1` 为背景音乐参考；设计 12 秒。首帧／首尾帧模式不能套用这组输入。

```text
Image 1 只确定站务员的外貌与服装；Image 2 负责车站空间与光线；Video 1 只参考缓慢推镜，不使用其中人物、服装和场景；Audio 1 只参考轻缓钢琴背景音乐。雨夜旧车站，站务员在室内检票台后，左手已握着钥匙；雾玻璃外是站台和一只手提灯，通向室内走廊的门在画面左侧。镜头1（0–5秒）：室内斜侧固定中景，她用右手擦开一小片水雾，看见手提灯，手停住。镜头2（5–9秒）：切到同侧肩后中景，沿玻璃内侧缓慢推进并在玻璃前停住，灯轻晃；轨道方向一声金属轻响后，她才转头，左手仍握钥匙。镜头3（9–12秒）：同侧中全景拍入她从头到膝和左侧门，她握紧钥匙走向门口并停住，望向画外。人物、钥匙、灯与空间连续。连续雨声、一声远处金属轻响与轻缓钢琴背景音乐，无对白，无字幕。
```

## 实际生成后的验收

先核对实际模式、素材绑定、输出时长及有无声音，再看每镜是否完成可见动作、因果与剪辑点；重点检查人物身份、手和钥匙、灯的位置、视线方向、声音触发、跨镜状态。若偏差出现，记录具体时间和画面，优先调整导致偏差的一项，保留未授权变化。画板、提示词和参数自检只能说明方案可交接，不能证明参考服从、节奏、音画同步或成片质量；本页示例均未经过真实视频生成验证。
