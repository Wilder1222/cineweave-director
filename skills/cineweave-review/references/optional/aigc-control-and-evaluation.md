# 可选参考：AIGC 控制选择与对照评审

涉及结构／身份／画风参考分工、局部编辑、生成方案比较或试片设计时加载。资料核验日期：2026-10-10。这里把官方文档和原作者公开实现转为制作决策，不是供应商执行器；版本、账号和界面支持仍按实际交接核验。摄影、表演、画风的内容决定由对应路由持有。

## 先判断缺的是内容还是控制

| 当前需求或失败 | 优先处理 | 必须保留的检查 |
| --- | --- | --- |
| 不清楚人物在做什么，光从哪里来 | 返回人物／场景／镜头设计，把事件写成可见关系 | 不用增加采样、参考权重或质量词掩盖设计缺口 |
| 机位、姿态、遮挡和空间必须准确 | 选择目标系统实际支持的姿态、深度、边缘或分区控制；必要时先做几何预演 | 控制图与目标取景一致；结构图不承担完整身份或表演 |
| 外观稳定，但需要新姿态和构图 | 使用身份／外观参考，另写姿态和空间约束 | 检查新角度、遮挡后复现及衣饰；一张正面图不能证明全角度一致 |
| 内容正确，画风漂移 | 固定内容，单独比较表现规则或风格参考 | 检查参考是否带入人物、建筑和文字；不把背景换了当成画风改善 |
| 只有一个区域需要修改 | 绑定实际来源，写清改变、保留及影响边界；可用时选择局部编辑 | 修改区域与邻接光影、边缘，以及未改区域都要重新比对 |
| 图像漂亮，运动却无法开始 | 修正关键帧姿态、接触、遮挡或运动路径 | 不把终态漂亮误判为初态可用 |
| 片段内容正确，但闪烁、色偏或交付失真 | 区分生成时序、引擎采样／曝光／色管和编码 | 按[画质与引擎流程](rendering-quality-workflows.md)定位责任，不先放大分辨率 |

这里是选择控制渠道的启发，不强制所有请求建立节点图、参考板或预演。单图和独立提示词只处理影响本次结果的维度。

## 结构、外观和风格参考分工

ControlNet 原作者实现展示边缘、姿态、深度等条件；IP-Adapter 原作者实现展示图像条件与文字、ControlNet 的组合。可借鉴的决策是**结构条件与图像特征可以分工**，不是任意模型都有这些插槽。原实现的基础模型、编码器及权重需匹配，不能将 SD 1.5 样例参数套入所有系统。[ControlNet 固定源码](https://github.com/lllyasviel/ControlNet/blob/ed85cd1e25a5ed592f7d8178495b4483de0331bf/README.md)、[IP-Adapter 固定源码](https://github.com/tencent-ailab/IP-Adapter/blob/62e4af9d0c1ac7d5f8dd386a0ccf2211346af1a2/README.md)。

先看实际预处理后的图：骨架会漏掉手指和道具接触，深度图不能表达材质，边缘图可能把不想保留的衣饰或背景也锁住；这些是本项目要求检查的风险，不是算法必然失败。IP-Adapter 原实现提醒默认图像处理会中心裁切非方形来源，因此参考中位于画边的关键物体需要检查是否进入编码输入。不要以“参考已上传”代替这一步。[IP-Adapter 输入裁切说明](https://github.com/tencent-ailab/IP-Adapter/blob/62e4af9d0c1ac7d5f8dd386a0ccf2211346af1a2/README.md)。

ComfyUI 的 ControlNet 节点分别暴露作用强度与开始／结束比例。制作工作表记录实际值及版本，试验时一次改变一个命名控制；权重过强与文字／身份参考争夺结果时，先检查控制图和职责冲突。不提供万能强度、步数或 CFG，也不因为图可连线就认定它适配目标模型。[ComfyUI ControlNet 官方示例](https://docs.comfy.org/tutorials/controlnet/controlnet)。

Midjourney 的 Style Reference 负责视觉表现，Omni Reference 属于 V7 人／物参考；官方提示 V8.X 使用 Edit Model。不能把身份、画风和编辑参考互换，也不能向 V8 稿直接附加 V7 的 `--oref`。具体参数与其他功能兼容由[Midjourney 适配](midjourney-projection.md)承接，本轮只复查了上述职责页，没有刷新整张历史能力表。[Style Reference](https://docs.midjourney.com/hc/en-us/articles/32180011136653-Style-Reference)、[Omni Reference](https://docs.midjourney.com/hc/en-us/articles/36285124473997-Omni-Reference)。

## 图像编辑的保留标准

OpenAI 当前指南将提示词和输出参数分开，并建议以实际输出继续做窄范围修改；图像生成文档仍列出准确文字、跨次一致性与精确构图的限制。把高保真或高质量视作可以比较的控制，不能把参数名称当作保留保证。`input_fidelity` 的支持随模型变化，旧笔记不应直接成为新模型请求。[Image prompting](https://developers.openai.com/api/docs/guides/image-prompting)、[Image generation](https://developers.openai.com/api/docs/guides/image-generation)。

蒙版是编辑引导，OpenAI 明示结果可能不精确遵循其形状；因此同时验收区域内修改、边缘过渡、区域外保留及光影因果。若局部编辑改变了未授权脸型、手势或构图，候选仍有失败；不能只裁出成功衣料宣布通过。[图像编辑与蒙版边界](https://developers.openai.com/api/docs/guides/image-generation#edit-images)。

局部中文交接示例，供支持参考编辑的外部流程使用：

```text
以所附原图为编辑来源，将人物右肩披着的深蓝围巾改为暗红羊毛围巾，保持原有宽度、绕颈方式、垂落位置和褶皱走向。新围巾在同一侧窗光下呈细软纤维和宽而弱的反光，领口遮挡及下方接触阴影随材质调整。保留人物五官结构、妆发、表情、手势、其余服装、桌面道具、摄影机位置、裁切和背景。只修改围巾及必要的邻接光影。
```

这段正文不是已附图、已画蒙版或已编辑的证明。未提供图时交付编辑设计与缺失依赖，不能假装看见原图。

## 视频方言不能平均成通用规则

图生视频先用真实输入定义可见初态，再描述人物、摄影机、环境如何变化。Runway Gen-4 指南支持运动主导、正向描述及逐次增加元素；Google 当前最佳实践也强调源图与运动的分工。这适用于其对应模式，不要求文生视频省略完整初态，也不把“短片聚焦一个事件”变成所有模型禁止多镜的规则。[Runway Gen-4 指南](https://help.runwayml.com/hc/en-us/articles/39789879462419-Gen-4-Video-Prompting-Guide)、[Google 视频最佳实践](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/video/best-practice)。

在 Runway Gen-4 适配稿中，把“不要运镜”改写为“摄影机固定”，不自动粘贴负向词库。有原生负向字段的其他系统则按其文档处理。用户要求的排除项仍保存在母稿／验收点，不能因改写方言而丢失。[Gen-4 正向措辞规则](https://help.runwayml.com/hc/en-us/articles/39789879462419-Gen-4-Video-Prompting-Guide)。

官方材料也可能互相冲突：Google 2025 年 Veo 3.1 博客示例使用对白引号，2026-10-07 更新的最佳实践建议说话人后用冒号、避免引号以减少文字入画。交接时保留准确台词，仅改变已核验模式的包裹语法；冲突、日期和适用范围写进证据，必要时设计最小试片，不替用户改词。[2025 年 Veo 3.1 博客](https://cloud.google.com/blog/products/ai-machine-learning/ultimate-prompting-guide-for-veo-3-1/)、[当前最佳实践](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/video/best-practice)。

历史教程只取方法：OpenAI Sora 2 Cookbook 已标记归档；停用页列出 Sora 2 与 Videos API 于 2026-09-24 移除。分镜、节拍和光色拆解仍可研究，不能列成 2026-10-10 的可执行候选，也不据旧教程填写参考槽位、时长或调用地址。[官方停用记录](https://developers.openai.com/api/docs/deprecations#2026-03-24-sora-2-video-generation-models-and-videos-api)。

## 最小有意义的对照

导演决定到 T2V、I2V、表演参考与剪辑的分工见[方案投影](video-platform-adaptation.md#导演方案到复制稿)。对照试片先确认复制稿实际继承了设计：谁何时获得哪条线索、谁继续持有物件、出点处于什么运动相位，以及关键声音由何种路径产生。复杂母稿和精练执行稿都可成立，只有必要事实另有真实输入承担时才删去；不以字数或大师名字数量判断控制完整。

先写一个会被结果否定的问题，例如“加入姿态条件是否保留了递物接触，同时没有改变脸和取景”。不是“哪个更电影感”。只在实际有权使用的素材和用户指定预算内设计试片；本 Skill 不执行收费生成。

1. 固定同一源图／素材版本、母稿、画幅、必要身份／场景和输出用途。诊断对照只改变一个变量；整体创意方向比较则明示多个变化，不伪称因果试验。
2. 记录实际模型、工作流／插件版本、权重来源和许可证、预处理输入、参数、控制时窗及原始输出。能固定 seed 时记录真实值；无法固定时保留这个差异。相同 seed 不是跨版本、硬件或平台的复现承诺。
3. 用不暗示预期胜者的候选编号，先查硬要求，再比较有意义的偏好。对静帧检查目标尺寸可读性及关键局部；对视频完整播放，并逐帧检查接触、遮挡前后、转身、切点和声音触发，不能用精选帧代替片段。
4. 少量候选只能支持本素材／本条件的结论。若随机差异可能解释结果，安排有限重复或标为不确定，不用一张成功图宣称方法普遍稳定。
5. 保留成功区间和失败反例，记录下一次只改哪个根因。修改参考、模型或色管后，重新检查受影响维度；不把旧验收结论继承到新输入。

非规范工作表按需使用以下列，不要求每次创作填表：

| 请求／候选 | 固定输入与版本 | 唯一变化或方向差异 | 预期可见结果 | 实际证据定位 | 结论与保留项 |
| --- | --- | --- | --- | --- | --- |
| 待试验 | 实际存在的来源；缺失则明确 | 控制图／表演／光／风格等 | 能被观察否定的标准 | 无媒体则填待取得 | 待验证，不评分 |

文字练习只能证明该次稿件的规划表现。单张图不能证明时间稳定，完整播放不能证明未取得的参数，分发测试不能证明媒体审美。结果和最小修复交给[评审与修复](../routes/review-repair.md)，不新增自动评委或通过阈值。
